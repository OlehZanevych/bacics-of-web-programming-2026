## Про цей репозиторій

Тут зібрані **конспекти всіх 16 лекцій** курсу. Це не слайди й не стенограма
занять — це самодостатні навчальні тексти, за якими можна опрацювати матеріал
самостійно.

Курс побудований **навколо проєкту**: п'ять індивідуальних завдань послідовно
нарощують складність — від статичного портфоліо без JavaScript до
клієнт-серверного застосунку React + Node.js + PostgreSQL, розгорнутого в
Інтернеті. Кожна лекція прямо працює на найближче завдання.

Аудиторний час розподілено нерівномірно й свідомо: HTML, CSS і синтаксис
JavaScript подаються концентровано (лекції 1–3 — саме тому вони найдовші й
розраховані на самостійне опрацювання), а основна частина занять відведена під
**React.js** (лекції 6–10) і **Node.js** (лекції 11–15) — теми, які найважче
засвоїти без супроводу.

## Як користуватися конспектами

1. **Читайте з відкритим редактором.** Кожен приклад коду призначений для
   того, щоб його **набрати руками** й подивитися результат. Пасивне читання
   конспекту з веброзробки дає приблизно нуль.
2. **Перед лекцією** перегляньте розділи «Мета» та «План» — щоб знати, на що
   звертати увагу.
3. **Після лекції** пройдіть «Контрольні запитання». Якщо на якесь не можете
   відповісти — поверніться до відповідного розділу.
4. **Практичні вправи** — не факультатив. Вони менші за індивідуальні
   завдання й тренують окремі навички.
5. **Розділ «Типові помилки»** читайте **до** того, як почнете завдання. Це
   зекономить години.

**Умовні позначення в текстах:**

- 🔑 — ключова ідея, яку варто запам'ятати
- ⚠️ — типова помилка або пастка
- 🧪 — місце, де треба відкрити DevTools і подивитися самому
- 📚 — поглиблене читання

## Наскрізні принципи курсу

Ці ідеї повторюються в кожній лекції — і в кожному реальному проєкті.

1. **Розділення відповідальності.** HTML — структура, CSS — вигляд,
   JS — поведінка. Контролер — HTTP, сервіс — логіка, репозиторій — дані.
2. **Одне джерело істини.** Стан визначає інтерфейс, а не навпаки.
3. **Ніколи не довіряйте клієнту.** Серверна валідація, параметризовані
   запити, перевірка прав на сервері — обов'язкові.
4. **Доступність — не додаткова функція.** Семантика, контраст, фокус,
   клавіатура — базовий рівень якості.
5. **Явне краще за неявне.** Явні залежності, коди помилок, конфігурації.
6. **Спочатку зрозуміло, потім швидко.** Оптимізація без вимірювання — марна
   робота.
7. **Помилки — частина інтерфейсу.** Чотири стани запиту, зрозумілі
   повідомлення, можливість повторити.

## Політика використання генеративного ШІ

Користуватися ШІ-асистентами (ChatGPT, Claude, GitHub Copilot) у курсі
**дозволено** — це частина сучасної інженерної практики. Умови:

1. У `README.md` кожної роботи має бути розділ **«Використання ШІ»**: які
   інструменти, для яких частин роботи, що зі згенерованого залишилося в коді.
2. Відповідальність за коректність, безпеку та якість коду повністю на вас.
   «Так згенерував ШІ» не є поясненням помилки.
3. **На захисті потрібно вміти пояснити будь-який рядок свого коду.**
   Нездатність це зробити прирівнюється до академічної недоброчесності навіть
   за наявності декларації.
