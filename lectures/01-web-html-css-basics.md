## Як користуватися цим конспектом

Це найдовша лекція курсу, і це навмисно. Вона охоплює те, що в багатьох курсах
розтягують на чотири заняття: як влаштований Web, як працює браузер, уся
практично потрібна HTML-розмітка та фундамент CSS. Аудиторного часу на все це
не вистачить — на лекції ми розберемо **найважче й найпомилковіше**, а решту ви
опрацюєте самостійно за цим конспектом.

Читайте його **з відкритим редактором**. Кожен приклад коду призначений для
того, щоб його набрати руками (не скопіювати!) і подивитися в браузері. Пасивне
читання конспекту з веброзробки дає приблизно нуль результату.

**Умовні позначення:**

- 🔑 — ключова ідея, яку варто запам'ятати
- ⚠️ — типова помилка
- 🧪 — місце, де треба відкрити DevTools і подивитися самому
- 📚 — поглиблене читання

## 1. Що таке Web і як він працює

### 1.1. Коротка історія (і чому вона корисна)

| Рік | Подія | Чому це важливо сьогодні |
|---|---|---|
| 1989–1991 | Тім Бернерс-Лі у ЦЕРН пропонує World Wide Web: HTML, HTTP, URL, перший браузер | Три ці технології досі є фундаментом. Ви вивчаєте буквально їх |
| 1994 | Засновано W3C | З'явився орган стандартизації |
| 1995 | Брендан Айк за 10 днів створює JavaScript для Netscape | Багато дивацтв мови — наслідок цих 10 днів |
| 1996 | CSS Level 1 | Розділення структури та оформлення |
| 1999–2005 | «Браузерні війни», XHTML, поява AJAX | Ідея оновлювати сторінку без перезавантаження |
| 2004 | Створено WHATWG (Apple, Mozilla, Opera) — незгода з курсом W3C на XHTML | Саме WHATWG сьогодні розвиває HTML |
| 2008–2015 | HTML5, ES5, ES6 (ES2015), сплеск мобільного вебу | Сучасний фундамент |
| 2019 | W3C і WHATWG домовляються: **HTML — living standard від WHATWG** | Немає «HTML 6». Стандарт оновлюється безперервно |
| 2020-ті | HTTP/2 і HTTP/3, ES-модулі, CSS Grid, компонентні фреймворки, Baseline | Те, що ми вивчаємо в цьому курсі |

🔑 **Ключовий висновок з історії:** веб-платформа **ніколи не ламає зворотну
сумісність**. Сторінка 1996 року відкриється в браузері 2026 року. Через це в
HTML і CSS багато історичних дивацтв — але й через це вивчені вами навички не
знеціняться раптово.

### 1.2. Хто визначає стандарти

| Організація | За що відповідає |
|---|---|
| **WHATWG** | HTML Living Standard, DOM, Fetch, URL, Streams |
| **W3C** | CSS, доступність (WAI, WCAG), SVG, WebRTC |
| **Ecma International (TC39)** | ECMAScript — стандарт мови JavaScript |
| **IETF** | HTTP, TCP/IP, TLS, URI (документи RFC) |
| **Baseline (W3C WebDX)** | Не стандарт, а **зведення** про підтримку можливостей у браузерах |

**Baseline** — важливе поняття, яке з'явилося недавно і дуже спрощує життя.
Замість того, щоб для кожної властивості перевіряти таблицю сумісності, ви
дивитеся на позначку:

- **Limited availability** — працює не скрізь, потрібен запасний варіант;
- **Newly available** — щойно запрацювало в усіх основних браузерах
  (Chrome, Edge, Firefox, Safari);
- **Widely available** — минуло 30 місяців від «newly», можна використовувати
  без вагань.

🧪 Зайдіть на [web.dev/baseline](https://web.dev/baseline) і подивіться, що
входить у Baseline поточного року. Позначки Baseline є на кожній сторінці MDN.

### 1.3. Клієнт-серверна архітектура

```
┌──────────────┐      HTTP-запит       ┌──────────────┐
│              │ ────────────────────► │              │
│   КЛІЄНТ     │                       │    СЕРВЕР    │
│  (браузер)   │ ◄──────────────────── │              │
│              │     HTTP-відповідь    │              │
└──────────────┘                       └──────┬───────┘
                                              │
                                       ┌──────▼───────┐
                                       │  База даних  │
                                       └──────────────┘
```

**Клієнт** (браузер) ініціює зв'язок, **сервер** відповідає. Сервер сам
«першим» звернутися до браузера не може — це принципове обмеження HTTP, яке
породило цілу низку технологій обходу (polling, Server-Sent Events, WebSocket —
про них у наступних курсах).

**HTTP не має стану (stateless):** сервер не пам'ятає попередній запит. Кожен
запит самодостатній. Щоб сервер «пам'ятав» користувача, стан передається явно —
у cookie, заголовку `Authorization` або параметрах запиту.

### 1.4. Від доменного імені до IP: DNS

Комп'ютери адресують одне одного за IP-адресами (`93.184.216.34`), люди — за
іменами (`example.com`). DNS (Domain Name System) — розподілена база, що
перекладає одне в інше.

Спрощений ланцюжок для `ami.lnu.edu.ua`:

1. **Кеш браузера** → **кеш ОС** → файл `hosts`. Знайшли — все, готово.
2. **Резолвер провайдера** (або `1.1.1.1`, `8.8.8.8`).
3. Резолвер питає **кореневий сервер**: «хто відповідає за `.ua`?»
4. Питає сервер зони **`.ua`**: «хто відповідає за `edu.ua`?»
5. Питає сервер **`edu.ua`** → отримує сервер `lnu.edu.ua`.
6. Питає його про `ami.lnu.edu.ua` → отримує IP-адресу.
7. Відповідь кешується на час TTL.

🧪 Спробуйте в терміналі: `nslookup lnu.edu.ua` або `dig lnu.edu.ua +short`.

### 1.5. URL: адреса ресурсу

```
https://user:pass@www.example.com:8443/catalog/books?genre=sci-fi&page=2#reviews
└─┬─┘   └───┬───┘ └──────┬───────┘└┬─┘└──────┬─────┘└────────┬────────┘└──┬───┘
схема   облікові дані     хост     порт     шлях          запит        фрагмент
        (майже не         (host)  (port)   (path)        (query)      (fragment)
         вживаються)
```

Що варто знати:

- **Схема** визначає протокол: `https:`, `http:`, `mailto:`, `tel:`, `file:`,
  `data:`, `blob:`.
- **Порт** за замовчуванням: 80 для `http`, 443 для `https`. Тому його зазвичай
  не пишуть.
- **Фрагмент** (`#reviews`) **на сервер не надсилається** — він обробляється
  лише браузером (прокручування до елемента з таким `id`). Це важлива деталь,
  на якій побудована маршрутизація старих SPA.
- **Query** — набір пар `ключ=значення`, розділених `&`. Спеціальні символи
  кодуються (`percent-encoding`): пробіл → `%20`, кирилиця → послідовність
  байтів UTF-8 у відсотковому кодуванні.

**Абсолютні та відносні URL.** Якщо ви на сторінці
`https://site.com/blog/post/1`:

| Посилання | Куди веде |
|---|---|
| `https://other.com/x` | абсолютний URL |
| `//other.com/x` | той самий протокол, що й у поточної сторінки |
| `/about` | `https://site.com/about` (від кореня сайту) |
| `next` | `https://site.com/blog/post/next` (відносно поточної теки) |
| `../list` | `https://site.com/blog/list` (на рівень вище) |
| `#comments` | та сама сторінка, прокрутка до `id="comments"` |

⚠️ Найчастіша помилка початківців — плутати `/images/photo.jpg` та
`images/photo.jpg`. Перше — від кореня домену, друге — від поточної теки. На
GitHub Pages, де сайт лежить не в корені (`user.github.io/repo/`), абсолютні
шляхи від кореня ламаються. **Для завдання №1 використовуйте відносні шляхи.**

### 1.6. HTTP: мова спілкування клієнта й сервера

**Запит:**

```http
GET /catalog/books?genre=sci-fi HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7) ...
Accept: text/html,application/xhtml+xml,*/*;q=0.8
Accept-Language: uk-UA,uk;q=0.9,en;q=0.8
Accept-Encoding: gzip, br
Cookie: session=abc123
Connection: keep-alive
```

**Відповідь:**

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 3241
Cache-Control: max-age=3600
Set-Cookie: session=abc123; HttpOnly; Secure; SameSite=Lax
Date: Tue, 01 Sep 2026 09:15:00 GMT

<!doctype html>
<html lang="uk">
...
```

Структура завжди однакова: **стартовий рядок → заголовки → порожній рядок →
тіло**.

#### Методи

| Метод | Призначення | Безпечний? | Ідемпотентний? |
|---|---|---|---|
| `GET` | отримати ресурс | так | так |
| `HEAD` | те саме, але лише заголовки | так | так |
| `POST` | створити / надіслати дані | ні | ні |
| `PUT` | замінити ресурс повністю | ні | так |
| `PATCH` | частково змінити ресурс | ні | ні |
| `DELETE` | видалити ресурс | ні | так |
| `OPTIONS` | дізнатися можливості (використовується в CORS) | так | так |

- **Безпечний (safe)** — не змінює стан сервера. `GET` не повинен нічого
  видаляти, навіть якщо технічно це можливо запрограмувати.
- **Ідемпотентний** — повторний однаковий запит дає той самий результат.
  Натиснути `DELETE` двічі — ресурс усе одно видалений один раз. А `POST`
  двічі — це два нові записи (звідси й попередження «не оновлюйте сторінку
  після оплати»).

🔑 HTML-форми вміють лише `GET` і `POST`. Решта методів доступні тільки через
JavaScript (`fetch`) — це знадобиться в лекціях 5 і 13.

#### Коди станів

| Клас | Значення | Найважливіші |
|---|---|---|
| **1xx** | інформаційні | `101 Switching Protocols` (WebSocket) |
| **2xx** | успіх | `200 OK`, `201 Created`, `204 No Content` |
| **3xx** | перенаправлення | `301` (назавжди), `302`/`307` (тимчасово), `304 Not Modified` |
| **4xx** | помилка клієнта | `400`, `401`, `403`, `404`, `409`, `422`, `429` |
| **5xx** | помилка сервера | `500`, `502`, `503`, `504` |

Варто розрізняти:

- **`401 Unauthorized`** — «я не знаю, хто ви» (немає або недійсний токен).
  Назва історично невдала: насправді це *unauthenticated*.
- **`403 Forbidden`** — «я знаю, хто ви, і вам не можна».
- **`404 Not Found`** — ресурсу немає.
- **`409 Conflict`** — конфлікт стану, наприклад дублювання унікального імені.

#### Важливі заголовки

| Заголовок | Пояснення |
|---|---|
| `Content-Type` | тип тіла: `text/html`, `application/json`, `multipart/form-data` |
| `Accept` | що клієнт готовий прийняти |
| `Cache-Control` | правила кешування (`max-age`, `no-store`, `must-revalidate`) |
| `Set-Cookie` / `Cookie` | механізм збереження стану |
| `Authorization` | облікові дані / токен |
| `Location` | куди перенаправити (з `3xx`) або де створений ресурс (з `201`) |
| `Content-Encoding` | стиснення: `gzip`, `br` (Brotli) |

#### Cookies за 60 секунд

Сервер надсилає `Set-Cookie: name=value; ...`, браузер зберігає і надсилає
назад із кожним запитом на цей домен. Ключові атрибути:

- `HttpOnly` — cookie недоступна з JavaScript (захист від крадіжки через XSS);
- `Secure` — надсилається лише через HTTPS;
- `SameSite=Lax|Strict|None` — захист від CSRF;
- `Max-Age` / `Expires` — час життя.

#### HTTPS, HTTP/2, HTTP/3

**HTTPS** — це HTTP поверх TLS. Дає три речі: шифрування (ніхто не прочитає),
цілісність (ніхто не змінить), автентифікацію сервера (ви точно на тому сайті).
Сьогодні HTTPS обов'язковий: без нього браузер не дасть доступу до геолокації,
камери, Service Workers, а Google понижує сайт у видачі. Безкоштовні
сертифікати видає Let's Encrypt.

**HTTP/1.1** — одне з'єднання = один запит за раз, звідси «head-of-line
blocking» і хитрощі минулого (склеювання файлів, спрайти, кілька доменів).

**HTTP/2** — мультиплексування (багато запитів одним з'єднанням), бінарний
формат, стиснення заголовків. Багато старих оптимізацій стали непотрібними.

**HTTP/3** — те саме поверх QUIC (UDP замість TCP), швидше встановлює з'єднання
і краще поводиться на нестабільній мережі.

🧪 Відкрийте DevTools → Network, увімкніть колонку «Protocol» і подивіться, за
яким протоколом завантажуються ресурси відомих вам сайтів.

## 2. Що відбувається, коли ви відкриваєте сторінку

Класичне запитання на співбесіді — і водночас чудова «карта» всього курсу.
Розберемо покроково для `https://example.com/about`.

1. **Розбір URL.** Браузер визначає схему, хост, шлях. Якщо введено не URL, а
   текст — передає його пошуковій системі.
2. **Перевірка HSTS.** Якщо домен у списку HSTS, `http://` примусово стає
   `https://`.
3. **DNS-резолв** (див. 1.4) → IP-адреса.
4. **TCP-з'єднання** (три-стороннє рукостискання SYN → SYN-ACK → ACK) або
   QUIC-з'єднання для HTTP/3.
5. **TLS-рукостискання**: узгодження версії й шифрів, перевірка сертифіката,
   вироблення ключів сеансу.
6. **HTTP-запит** `GET /about`.
7. **Обробка на сервері**: маршрутизація, звернення до бази, генерація HTML
   (або віддача статичного файлу).
8. **HTTP-відповідь**: код стану, заголовки, тіло.
9. **Парсинг HTML** браузером із поступовою побудовою **DOM**.
10. Під час парсингу знаходяться посилання на **CSS**, **JS**, зображення,
    шрифти → нові запити (частина з них блокує рендеринг).
11. Побудова **CSSOM**, потім **Render Tree**.
12. **Layout** (обчислення геометрії) → **Paint** (малювання) →
    **Compositing** (складання шарів).
13. Виконання JavaScript, який може змінити DOM/CSSOM → часткові перерахунки.
14. Подія `DOMContentLoaded`, згодом `load`.

📚 Детальний розбір англійською: репозиторій
[what-happens-when](https://github.com/alex/what-happens-when) — там ця сама
історія на 30 сторінок, аж до роботи клавіатурного контролера.

## 3. Як браузер перетворює код на пікселі

### 3.1. Критичний шлях рендерингу

```
HTML ──parse──► DOM ─┐
                     ├──► Render Tree ──► Layout ──► Paint ──► Composite
CSS  ──parse──► CSSOM┘
```

- **DOM (Document Object Model)** — дерево об'єктів, що відповідає структурі
  документа. Саме з ним працює JavaScript (лекція 4).
- **CSSOM** — дерево стилів.
- **Render Tree** — лише те, що видно (елементи з `display: none` не
  потрапляють; а от `visibility: hidden` — потрапляє, бо займає місце).
- **Layout (reflow)** — обчислення розмірів і позицій. Дорога операція.
- **Paint** — заливка пікселів.
- **Composite** — складання шарів на GPU. Найдешевша стадія.

🔑 **Практичний наслідок:** анімувати `transform` і `opacity` дешево (тільки
composite), а `width`, `height`, `top`, `left`, `margin` — дорого (повний
layout). Це пряма вимога Завдання №2.

### 3.2. Що блокує рендеринг

- **CSS блокує рендеринг** (render-blocking): браузер не покаже вміст, поки не
  побудує CSSOM — інакше сторінка «блимнула» б нестилізованим текстом.
  Тому CSS підключають у `<head>`.
- **Синхронний `<script>` блокує парсинг**: браузер зупиняє побудову DOM,
  завантажує й виконує скрипт. Тому скрипти історично клали в кінець `<body>`.

Сучасне рішення — атрибути `defer` і `async`:

```html
<!-- Завантажується паралельно, виконується ПІСЛЯ побудови DOM,
     порядок скриптів зберігається. Це те, що потрібно в 95% випадків. -->
<script src="app.js" defer></script>

<!-- Завантажується паралельно, виконується ОДРАЗУ після завантаження,
     порядок не гарантується. Для незалежних скриптів (аналітика). -->
<script src="analytics.js" async></script>

<!-- ES-модулі мають defer за замовчуванням -->
<script type="module" src="main.js"></script>
```

### 3.3. Core Web Vitals — як вимірюють «швидкість»

| Метрика | Що вимірює | Добре |
|---|---|---|
| **LCP** (Largest Contentful Paint) | коли з'явився найбільший елемент | ≤ 2.5 с |
| **INP** (Interaction to Next Paint) | наскільки швидко сторінка реагує на дії | ≤ 200 мс |
| **CLS** (Cumulative Layout Shift) | наскільки «стрибає» верстка | ≤ 0.1 |

⚠️ **CLS і зображення.** Якщо не вказати `width` і `height` у `<img>`, браузер
не знає, скільки місця зарезервувати, і після завантаження картинки текст
стрибає. Це найпоширеніша причина поганого CLS — і саме тому в Завданні №1
атрибути розмірів обов'язкові.

## 5. HTML: мова структури

### 5.1. Що таке HTML і чим він не є

**HTML (HyperText Markup Language)** — мова *розмітки*, а не програмування. Вона
описує **сенс** частин документа: це заголовок, це абзац, це список, це
навігація. Вона **не** описує, як воно виглядає — за це відповідає CSS.

🔑 **Найважливіша ідея всієї лекції:** HTML описує *що це таке*, CSS — *як воно
виглядає*, JavaScript — *як воно поводиться*. Порушення цього розподілу — джерело
більшості проблем у верстці новачків.

### 5.2. Анатомія елемента

```html
<a href="https://lnu.edu.ua" class="link link--external">ЛНУ</a>
│└┬┘ └──────────┬─────────┘  └───────┬────────────────┘└─┬─┘└┬┘
│ │             │                    │                   │   └── закривальний тег
│ │             │                    │                   └────── вміст
│ │             │                    └────────────────────────── ще один атрибут
│ │             └─────────────────────────────────────────────── атрибут (ім'я="значення")
│ └───────────────────────────────────────────────────────────── ім'я елемента
└─────────────────────────────────────────────────────────────── відкривальний тег
```

**Порожні (void) елементи** не мають вмісту й закривального тега:
`<img>`, `<br>`, `<hr>`, `<input>`, `<meta>`, `<link>`, `<source>`.
Писати `<br/>` не помилка, але й не потрібно (це спадок XHTML).

**Атрибути:** значення бажано брати в лапки. Логічні атрибути
(`required`, `disabled`, `checked`, `hidden`) не потребують значення — сама їх
наявність означає «увімкнено».

### 5.3. Скелет документа

```html
<!doctype html>
<html lang="uk">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Портфоліо — Ім'я Прізвище</title>
    <meta name="description" content="Студентське портфоліо: проєкти, навички, контакти.">
    <link rel="icon" href="favicon.svg" type="image/svg+xml">
    <link rel="stylesheet" href="css/style.css">
  </head>
  <body>
    <!-- видимий вміст -->
    <script src="js/main.js" defer></script>
  </body>
</html>
```

Розберемо кожен рядок — тут немає нічого зайвого:

| Рядок | Навіщо |
|---|---|
| `<!doctype html>` | Перемикає браузер у стандартний режим. Без нього — «quirks mode», де блокова модель поводиться як у 1998 році |
| `lang="uk"` | Мова документа: потрібна екранним читачам (вимова), перенесенню слів, перекладачам, пошуковим системам |
| `<meta charset="utf-8">` | Кодування. **Має бути в перших 1024 байтах документа.** Без нього кирилиця перетворюється на «кракозябри» |
| `<meta name="viewport" ...>` | **Без цього рядка мобільної верстки не існує.** Мобільний браузер емулює екран ~980 px і масштабує сторінку. Цей тег каже: використовуй реальну ширину пристрою |
| `<title>` | Заголовок вкладки, результат пошуку, назва закладки. Найважливіший текст на сторінці для SEO |
| `<meta name="description">` | Опис у результатах пошуку (150–160 символів) |
| `<link rel="icon">` | Іконка вкладки |
| `<link rel="stylesheet">` | Підключення CSS у `<head>` (див. 3.2) |
| `<script defer>` | Скрипт, що не блокує парсинг |

### 5.4. Метадані для соцмереж (Open Graph)

Коли посилання на ваш сайт кидають у месенджер, попередній перегляд будується
за цими тегами:

```html
<meta property="og:type" content="website">
<meta property="og:title" content="Портфоліо — Ім'я Прізвище">
<meta property="og:description" content="Проєкти, навички та контакти студента ФПМІ.">
<meta property="og:image" content="https://example.com/og-cover.png">
<meta property="og:url" content="https://example.com/">
<meta name="twitter:card" content="summary_large_image">
```

Рекомендований розмір зображення — 1200 × 630 px.

## 6. HTML: текст, посилання, зображення, медіа

### 6.1. Текстові елементи

```html
<h1>Головний заголовок сторінки</h1>
<h2>Розділ</h2>
<h3>Підрозділ</h3>

<p>Абзац тексту. Переноси рядків у коді <strong>не</strong> створюють
переносів на сторінці — кілька пробілів і переносів схлопуються в один пробіл.</p>

<p>Важливість: <strong>критично важливо</strong>.
   Наголос: <em>саме це</em> слово.
   Просто жирний без сенсу: <b>назва товару</b>.
   Просто курсив без сенсу: <i>науковий термін</i>.</p>

<p>Скорочення: <abbr title="Каскадні таблиці стилів">CSS</abbr>.</p>
<p>Дата: <time datetime="2026-09-01">1 вересня 2026</time>.</p>
<p>Код у тексті: <code>box-sizing: border-box</code>.</p>
<p>Виділено: <mark>знайдений збіг</mark>.</p>
<p>Було <del>100 грн</del>, стало <ins>80 грн</ins>.</p>

<blockquote cite="https://example.com/article">
  <p>Будь-який дурень може написати код, зрозумілий комп'ютеру. Хороші
     програмісти пишуть код, зрозумілий людям.</p>
  <footer>— <cite>Мартін Фаулер, «Рефакторинг»</cite></footer>
</blockquote>

<pre><code>function greet(name) {
  return `Привіт, ${name}!`;
}</code></pre>
```

🔑 **`<strong>` проти `<b>`, `<em>` проти `<i>`.** Візуально однаково, семантично
різне. `<strong>` означає *важливість* (екранний читач може змінити інтонацію),
`<b>` — просто напівжирне накреслення без додаткового сенсу. За замовчуванням
використовуйте `<strong>` і `<em>`.

**Списки:**

```html
<!-- Невпорядкований -->
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

<!-- Упорядкований, можна почати не з одиниці й перевернути -->
<ol start="3" reversed>
  <li>Третій крок</li>
  <li>Другий крок</li>
</ol>

<!-- Список означень: ідеальний для глосарію або «характеристик» -->
<dl>
  <dt>DOM</dt>
  <dd>Об'єктна модель документа — деревоподібне подання HTML у пам'яті браузера.</dd>
  <dt>CSSOM</dt>
  <dd>Об'єктна модель CSS.</dd>
</dl>
```

⚠️ Усередині `<ul>`/`<ol>` безпосередніми дітьми можуть бути **лише** `<li>`
(і `<script>`/`<template>`). `<div>` між `<ul>` та `<li>` — помилка валідації.

### 6.2. Посилання

```html
<a href="about.html">Про мене</a>                        <!-- відносне -->
<a href="https://lnu.edu.ua">Сайт університету</a>       <!-- абсолютне -->
<a href="#contacts">До контактів</a>                     <!-- якір на сторінці -->
<a href="mailto:oleh@example.com">Написати</a>
<a href="tel:+380671234567">Зателефонувати</a>
<a href="cv.pdf" download="Zanevych-CV.pdf">Завантажити резюме</a>

<a href="https://github.com/user" target="_blank" rel="noopener noreferrer">
  GitHub
</a>
```

**Про `target="_blank"`.** Відкриває в новій вкладці. Разом із ним пишуть
`rel="noopener noreferrer"`:

- `noopener` — нова сторінка не отримає доступу до `window.opener` (історична
  вразливість; сучасні браузери додають це автоматично, але явність краща);
- `noreferrer` — не передавати заголовок `Referer`.

⚠️ **Правило доступності:** відкриття в новій вкладці має бути *очікуваним*.
Якщо ви так робите, попередьте користувача — іконкою або текстом
«(відкриється в новій вкладці)». Раптова нова вкладка ламає кнопку «Назад» і
дезорієнтує людей, що користуються екранним читачем.

⚠️ **Текст посилання має бути осмисленим поза контекстом.** Екранні читачі
вміють читати список усіх посилань сторінки. Список із десяти «Детальніше» —
марний.

| Погано | Добре |
|---|---|
| `<a href="...">Тут</a>` | `<a href="...">Умови вступу на ФПМІ</a>` |
| `<a href="...">Детальніше</a>` | `<a href="...">Детальніше про курс «Основи web»</a>` |

### 6.3. Зображення

```html
<img src="img/photo.jpg"
     alt="Студент за ноутбуком у бібліотеці університету"
     width="800" height="600"
     loading="lazy"
     decoding="async">
```

| Атрибут | Чому обов'язковий |
|---|---|
| `alt` | Текстова альтернатива: озвучується екранним читачем, показується, якщо картинка не завантажилася, індексується пошуком |
| `width`/`height` | Резервують місце → немає стрибка верстки (CLS). Вказуються **без** одиниць, це співвідношення сторін |
| `loading="lazy"` | Зображення нижче першого екрана завантажаться, лише коли до них дійдуть |
| `decoding="async"` | Декодування не блокує головний потік |

**Як писати `alt`:**

| Ситуація | `alt` |
|---|---|
| Змістовне зображення | Опис того, **що на ньому важливо**: `alt="Графік зростання відвідувань із 1 200 до 4 800 за квартал"` |
| Зображення-посилання | Опис **призначення**: `alt="Головна сторінка"` |
| Суто декоративне | `alt=""` (порожній, але **обов'язковий**) — читач його пропустить |
| Текст на картинці | Продублювати текст |

⚠️ Не починайте з «Зображення...» або «Фото...» — екранний читач і так скаже,
що це графіка. Не дублюйте підпис, що вже є поруч у `<figcaption>`.

**Адаптивні зображення:**

```html
<!-- Різні РОЗМІРИ того самого зображення: браузер сам обере потрібний -->
<img src="photo-800.jpg"
     srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w"
     sizes="(min-width: 1200px) 1000px, (min-width: 768px) 50vw, 100vw"
     alt="Панорама Львова з Високого замку"
     width="1600" height="900">

<!-- Різні ЗОБРАЖЕННЯ або формати: обирає розробник -->
<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <source media="(max-width: 600px)" srcset="hero-mobile.jpg">
  <img src="hero.jpg" alt="Робоче місце розробника" width="1200" height="800">
</picture>
```

🔑 Різниця: `srcset` — «те саме зображення, різна роздільність, вибирає браузер».
`<picture>` — «різні зображення або формати, вибираю я». Обидва обов'язкові в
Завданні №1.

**Формати:** `AVIF` (найкраще стиснення) → `WebP` (широка підтримка) → `JPEG`
(фото) / `PNG` (прозорість) / `SVG` (векторна графіка, іконки, логотипи).

**Рисунок із підписом:**

```html
<figure>
  <img src="img/lviv.jpg" alt="Площа Ринок у сонячний день" width="1200" height="800">
  <figcaption>Площа Ринок, Львів. Фото автора, травень 2026.</figcaption>
</figure>
```

### 6.4. Медіа

```html
<video src="demo.mp4" controls muted playsinline
       poster="demo-poster.jpg" width="800" height="450">
  Ваш браузер не підтримує відео. <a href="demo.mp4">Завантажити</a>.
</video>

<audio src="track.mp3" controls preload="metadata"></audio>
```

⚠️ Ніколи не додавайте `autoplay` зі звуком — браузери це блокують, а
користувачі ненавидять.

## 7. HTML: семантична структура сторінки

### 7.1. Чому не можна все зробити на `<div>`

`<div>` — елемент **без жодного сенсу**, «коробка загального призначення».
Сторінка з самих `<div>` виглядає для браузера як суцільна каша. Наслідки:

- **екранні читачі** не можуть побудувати карту сторінки й перескакувати між
  розділами (незрячий користувач змушений прослухати все підряд);
- **пошукові системи** гірше розуміють, де основний зміст;
- **режим читання** в браузері не працює;
- **ваш власний CSS** стає нечитабельним: `.wrapper .container .inner .box`.

### 7.2. Секційні елементи

```html
<body>
  <a class="skip-link" href="#main">Перейти до основного вмісту</a>

  <header>                       <!-- шапка сайту або секції -->
    <a href="/" class="logo">Ім'я Прізвище</a>
    <nav aria-label="Основна навігація">
      <ul>
        <li><a href="#about" aria-current="page">Про мене</a></li>
        <li><a href="#skills">Навички</a></li>
        <li><a href="#contacts">Контакти</a></li>
      </ul>
    </nav>
  </header>

  <main id="main">               <!-- РІВНО ОДИН на сторінку -->
    <h1>Портфоліо студента ФПМІ</h1>

    <section id="about">         <!-- тематичний розділ, ЗАВЖДИ із заголовком -->
      <h2>Про мене</h2>
      <p>…</p>
    </section>

    <section id="books">
      <h2>Улюблені книги</h2>

      <article>                  <!-- самодостатній фрагмент -->
        <h3>«Чистий код», Роберт Мартін</h3>
        <p>…</p>
      </article>

      <article>
        <h3>«Кобзар», Тарас Шевченко</h3>
        <p>…</p>
      </article>
    </section>

    <aside>                      <!-- дотичний, але не основний вміст -->
      <h2>Цікавий факт</h2>
      <p>…</p>
    </aside>
  </main>

  <footer>
    <address>
      Зв'язок: <a href="mailto:me@example.com">me@example.com</a>
    </address>
    <p><small>© 2026 Ім'я Прізвище</small></p>
  </footer>
</body>
```

| Елемент | Коли використовувати | Коли **не** використовувати |
|---|---|---|
| `<header>` | Шапка сайту або вступна частина секції/статті | Для будь-якого блоку зверху |
| `<nav>` | **Основні** блоки навігації | Для кожного набору посилань поспіль |
| `<main>` | Унікальний основний вміст. **Рівно один, не вкладений** | Ніколи не дублювати |
| `<section>` | Тематичний розділ, що **має заголовок** | Як заміна `<div>` для стилізації |
| `<article>` | Самодостатній фрагмент: пост, картка товару, коментар | Для довільного блоку |
| `<aside>` | Бічна панель, примітка, реклама — дотичне | Для основного вмісту |
| `<footer>` | Підвал сайту або секції | — |
| `<div>` | Коли **справді** потрібна лише обгортка для стилів | Замість семантичних елементів |

🔑 **Тест на `<section>`:** якщо ви не можете придумати для блоку заголовок —
це, найімовірніше, `<div>`, а не `<section>`.

**Ще два корисні елементи:**

```html
<!-- Розкривний блок БЕЗ JavaScript -->
<details>
  <summary>Які предмети я вивчав?</summary>
  <p>Математичний аналіз, алгебра, дискретна математика…</p>
</details>

<!-- Діалогове вікно (нативне, з фокус-пасткою) -->
<dialog id="modal">
  <p>Вміст модального вікна</p>
  <form method="dialog"><button>Закрити</button></form>
</dialog>
```

### 7.3. Ієрархія заголовків

Заголовки утворюють **зміст документа**. Для незрячого користувача це головний
спосіб навігації.

Правила:

1. **Рівно один `<h1>`** — головна тема сторінки.
2. Рівні **не перестрибують**: після `<h2>` йде `<h3>`, а не `<h4>`.
3. Заголовок обирається **за рівнем у структурі**, а не за бажаним розміром
   шрифту. Потрібен маленький заголовок — зменште його в CSS.

```html
<!-- ✅ Правильно -->
<h1>Портфоліо</h1>
  <h2>Освіта</h2>
    <h3>Університет</h3>
    <h3>Школа</h3>
  <h2>Навички</h2>

<!-- ❌ Неправильно: перестрибування рівня і вибір за розміром -->
<h1>Портфоліо</h1>
  <h4>Освіта</h4>        <!-- бо «h2 надто великий» -->
```

🧪 У DevTools встановіть розширення для перевірки структури заголовків або
скористайтеся вкладкою Accessibility → Full-page accessibility tree.

## 8. HTML: таблиці

Таблиці призначені **для табличних даних**, а не для верстки (це практика
1990-х, яка сьогодні неприпустима — для розкладки є Flexbox і Grid, лекція 2).

```html
<table>
  <caption>Розклад занять на понеділок</caption>
  <thead>
    <tr>
      <th scope="col">Час</th>
      <th scope="col">Дисципліна</th>
      <th scope="col">Аудиторія</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">08:30</th>
      <td>Основи web програмування</td>
      <td>247</td>
    </tr>
    <tr>
      <th scope="row">10:10</th>
      <td>Математичний аналіз</td>
      <td>115</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <td colspan="3">Розклад може змінюватися</td>
    </tr>
  </tfoot>
</table>
```

Ключові моменти:

- **`<caption>`** — назва таблиці, перший елемент усередині `<table>`.
  Озвучується екранним читачем перед вмістом.
- **`<th scope="col">`** — заголовок стовпця, **`scope="row"`** — рядка. Без
  `scope` екранний читач не може пов'язати комірку з її заголовком, і таблиця
  перетворюється на потік беззмістовних чисел.
- `colspan` / `rowspan` — об'єднання комірок.

## 9. HTML: форми

Форми — найскладніша й найважливіша частина HTML. Через них проходять усі дані
від користувача.

### 9.1. Базова структура

```html
<form action="/subscribe" method="post" novalidate>
  <fieldset>
    <legend>Зворотний зв'язок</legend>

    <div class="field">
      <label for="name">Ім'я</label>
      <input type="text" id="name" name="name"
             required minlength="2" maxlength="60"
             autocomplete="name">
    </div>

    <div class="field">
      <label for="email">Електронна пошта</label>
      <input type="email" id="email" name="email"
             required autocomplete="email"
             placeholder="you@example.com">
      <small class="hint">Ми не передаємо адресу третім особам.</small>
    </div>

    <div class="field">
      <label for="topic">Тема звернення</label>
      <select id="topic" name="topic" required>
        <option value="">— оберіть тему —</option>
        <option value="collab">Співпраця</option>
        <option value="question">Питання</option>
        <option value="other">Інше</option>
      </select>
    </div>

    <div class="field">
      <label for="message">Повідомлення</label>
      <textarea id="message" name="message" rows="5"
                required minlength="10" maxlength="1000"></textarea>
    </div>

    <fieldset>
      <legend>Бажаний спосіб відповіді</legend>
      <label><input type="radio" name="reply" value="email" checked> Поштою</label>
      <label><input type="radio" name="reply" value="phone"> Телефоном</label>
    </fieldset>

    <label class="checkbox">
      <input type="checkbox" name="consent" required>
      Погоджуюся на обробку персональних даних
    </label>

    <button type="submit">Надіслати</button>
    <button type="reset">Очистити</button>
  </fieldset>
</form>
```

### 9.2. `<label>` — не декорація, а механізм

```html
<!-- Спосіб 1: явний зв'язок через for/id (рекомендований) -->
<label for="email">Пошта</label>
<input type="email" id="email" name="email">

<!-- Спосіб 2: обгортання -->
<label>Пошта <input type="email" name="email"></label>
```

Що дає правильний `<label>`:

1. Клік по підпису ставить фокус у поле (і перемикає checkbox) — це помітно
   зручніше, особливо на сенсорних екранах, де важко влучити в маленький
   квадратик.
2. Екранний читач озвучує підпис, коли користувач потрапляє у поле.
3. Збільшується область натискання — вимога WCAG.

⚠️ **`placeholder` не замінює `<label>`.** Плейсхолдер зникає, щойно почали
вводити текст; має низький контраст; не озвучується частиною екранних читачів.
Використовуйте його лише як **приклад формату**, не як підпис.

### 9.3. Типи полів

| `type` | Що дає |
|---|---|
| `text` | звичайний текст |
| `email` | перевірка формату, на мобільному — клавіатура з `@` |
| `tel` | цифрова клавіатура (формат не перевіряється!) |
| `url` | перевірка URL |
| `number` | лише числа, стрілки, `min`/`max`/`step` |
| `range` | повзунок |
| `date`, `time`, `datetime-local`, `month`, `week` | нативні вибирачі |
| `password` | приховані символи |
| `search` | поле пошуку з кнопкою очищення |
| `color` | палітра |
| `file` | вибір файлу (`accept`, `multiple`) |
| `checkbox`, `radio` | прапорець, перемикач |
| `hidden` | приховане службове значення |

🔑 Правильний `type` — це насамперед **зручність на мобільному**: під кожен тип
операційна система показує відповідну клавіатуру. Це безкоштовна перемога в UX.

### 9.4. Вбудована валідація

```html
<input type="text"   required minlength="2" maxlength="60">
<input type="number" min="1" max="100" step="1">
<input type="text"   pattern="[A-Za-zА-Яа-яІіЇїЄєҐґ'\- ]+"
       title="Лише літери, апостроф і дефіс">
<input type="email"  required multiple>   <!-- кілька адрес через кому -->
```

Браузер сам перевірить поля перед відправкою і покаже повідомлення. Атрибут
`novalidate` на `<form>` вимикає цю поведінку (знадобиться, коли ми писатимемо
власну валідацію на JS у лекціях 4 і 9).

Стилізувати стани можна псевдокласами:

```css
input:required            { border-left: 3px solid var(--color-accent); }
input:user-invalid        { border-color: var(--color-danger); }
input:user-valid          { border-color: var(--color-success); }
input:focus-visible       { outline: 2px solid var(--color-accent); outline-offset: 2px; }
```

🔑 `:user-invalid` замість `:invalid` — принципово важливо для UX: `:invalid`
підсвічує порожнє обов'язкове поле **одразу після завантаження сторінки**
(користувач ще нічого не зробив, а на нього вже «кричать»), а `:user-invalid`
спрацьовує лише після взаємодії.

### 9.5. `autocomplete` — недооцінений атрибут

```html
<input type="text"     name="fname"  autocomplete="given-name">
<input type="text"     name="lname"  autocomplete="family-name">
<input type="email"    name="email"  autocomplete="email">
<input type="tel"      name="phone"  autocomplete="tel">
<input type="password" name="pass"   autocomplete="current-password">
<input type="password" name="new"    autocomplete="new-password">
```

Правильні значення дозволяють браузеру й менеджеру паролів заповнити форму за
секунду. Для людей з моторними порушеннями це не зручність, а умова
користування сайтом (це прямо прописано у WCAG 2.2, критерій 1.3.5).

### 9.6. Кнопки

```html
<button type="submit">Надіслати</button>  <!-- за замовчуванням у формі -->
<button type="reset">Скинути</button>
<button type="button">Просто кнопка</button>
```

⚠️ **Найпоширеніша помилка:** `<button>` усередині форми **за замовчуванням має
`type="submit"`**. Якщо ви повісили на неї JS-обробник і не вказали
`type="button"`, форма відправиться і сторінка перезавантажиться.

⚠️ **Друга найпоширеніша:** `<div onclick="...">` замість `<button>`. Такий
«кнопка-div» недоступний з клавіатури, не має ролі для екранного читача і не
реагує на пробіл/Enter. Правило просте: **дія → `<button>`, перехід →
`<a href>`**.

## 10. Доступність: базовий рівень

**Доступність (accessibility, a11y)** — це можливість користуватися сайтом
людям із порушеннями зору, слуху, моторики чи когнітивних функцій. За оцінками
ВООЗ, це понад мільярд людей. Крім того, доступність допомагає всім: субтитри
дивляться в транспорті, високий контраст рятує на сонці, керування з клавіатури
пришвидшує роботу.

### 10.1. Принципи POUR (WCAG)

| Принцип | Що означає | Приклад із нашого курсу |
|---|---|---|
| **P**erceivable (сприйнятність) | Інформацію можна сприйняти | `alt` до зображень, контраст ≥ 4.5:1 |
| **O**perable (керованість) | Усім можна керувати | усе доступно з клавіатури, видимий фокус |
| **U**nderstandable (зрозумілість) | Зміст і робота передбачувані | `lang`, зрозумілі підписи й помилки |
| **R**obust (надійність) | Працює з допоміжними технологіями | валідний семантичний HTML |

Рівні відповідності: **A** (мінімум), **AA** (галузевий стандарт, вимога
законодавства ЄС і України для держсайтів), **AAA** (максимум).

### 10.2. Що робити вже зараз

1. **Семантика замість `<div>`** — це 80% доступності «безкоштовно».
2. **Один `<h1>`, коректна ієрархія заголовків.**
3. **`alt` для всіх зображень.**
4. **`<label>` для всіх полів форми.**
5. **Контраст ≥ 4.5:1** для звичайного тексту, ≥ 3:1 для великого (від 24 px
   або 19 px напівжирного) та для меж елементів керування.
6. **Видимий фокус:**

   ```css
   /* ❌ Ніколи так не робіть */
   *:focus { outline: none; }

   /* ✅ Замініть на власний, помітний */
   :focus-visible {
     outline: 3px solid var(--color-focus);
     outline-offset: 2px;
   }
   ```

7. **Skip-link** — перше посилання на сторінці, що дозволяє пропустити
   навігацію:

   ```html
   <a class="skip-link" href="#main">Перейти до основного вмісту</a>
   ```

   ```css
   .skip-link {
     position: absolute;
     left: -9999px;
   }
   .skip-link:focus {
     left: 1rem;
     top: 1rem;
     z-index: 100;
     background: var(--color-bg);
     padding: 0.75rem 1rem;
   }
   ```

8. **Порядок у DOM = логічний порядок читання.** CSS може переставити елементи
   візуально, але екранний читач і клавіатура йдуть за DOM. Розбіжність
   дезорієнтує.

### 10.3. ARIA: перше правило

**ARIA (Accessible Rich Internet Applications)** — набір атрибутів, що додають
семантику там, де HTML її не має.

> 🔑 **Перше правило ARIA: не використовуйте ARIA.**
> Якщо існує HTML-елемент із потрібною семантикою — використайте його.
> `<button>` кращий за `<div role="button" tabindex="0">`.

Коли ARIA все ж потрібна:

```html
<!-- Іконкове посилання без тексту -->
<a href="https://github.com/user" aria-label="Профіль на GitHub">
  <svg aria-hidden="true">…</svg>
</a>

<!-- Позначення поточної сторінки -->
<a href="/about" aria-current="page">Про мене</a>

<!-- Кілька блоків навігації треба розрізнити -->
<nav aria-label="Основна навігація">…</nav>
<nav aria-label="Навігація в підвалі">…</nav>

<!-- Розкривний елемент (з JS) -->
<button aria-expanded="false" aria-controls="menu">Меню</button>
<ul id="menu" hidden>…</ul>
```

⚠️ Неправильна ARIA **гірша за її відсутність**: вона перекриває справжню
семантику й може зробити елемент непридатним.

### 10.4. Інструменти перевірки

- **Lighthouse** (DevTools) — швидкий автоматичний аудит.
- **axe DevTools** — розширення, точніші перевірки.
- **WAVE** — візуалізація проблем прямо на сторінці.
- **WebAIM Contrast Checker** — перевірка контрасту пари кольорів.
- **Клавіатура** — просто пройдіть сторінку `Tab`-ом. Видно фокус? Логічний
  порядок? Усе доступно?

🔑 Автоматика ловить приблизно 30–40% проблем. Решту знаходить лише ручна
перевірка.

## 11. CSS: як воно взагалі влаштоване

### 11.1. Синтаксис

```css
селектор {
  властивість: значення;
  властивість: значення;
}
```

```css
.card {
  padding: 1.5rem;
  border-radius: 8px;
  background-color: #ffffff;
}
```

**At-правила** (починаються з `@`):

```css
@import url("reset.css");
@media (min-width: 768px) { … }
@supports (display: grid) { … }
@keyframes fade-in { … }
@font-face { … }
@layer base, components, utilities;
```

### 11.2. Три способи підключити CSS

```html
<!-- 1. Зовнішній файл — ЄДИНИЙ правильний варіант для реальних проєктів -->
<link rel="stylesheet" href="css/style.css">

<!-- 2. Вбудований блок — лише для критичних стилів або демо -->
<style> body { margin: 0; } </style>

<!-- 3. Інлайновий атрибут — уникайте (див. нижче) -->
<p style="color: red;">Текст</p>
```

Чому зовнішній файл:

- кешується браузером → сторінки завантажуються швидше;
- один файл для всього сайту → зміна в одному місці;
- відокремлення оформлення від структури;
- інлайнові стилі мають величезну специфічність і їх майже неможливо
  перевизначити.

⚠️ В Завданні №1 інлайнові стилі та `<style>` у розмітці **заборонені**.

### 11.3. Коментарі

```css
/* Однорядковий */

/* ============================================
   Блок: Картка проєкту
   ============================================ */
```

## 12. CSS: селектори

### 12.1. Базові

```css
p              { }  /* за іменем елемента */
.card          { }  /* за класом      — основний інструмент */
#header        { }  /* за id          — уникайте в стилях */
*              { }  /* усі елементи   — обережно */
```

🔑 **Стилізуйте класами.** `id` унікальний, має надмірну специфічність і
призводить до «війни важливості». `id` лишіть для якорів і зв'язку
`label`/`for`.

### 12.2. Групування й комбінатори

```css
h1, h2, h3               { }  /* група: до кожного з них */

.card p                  { }  /* НАЩАДОК: будь-який p всередині .card */
.card > p                { }  /* ДОЧІРНІЙ: лише прямий нащадок */
h2 + p                   { }  /* СУСІДНІЙ: перший p одразу після h2 */
h2 ~ p                   { }  /* ЗАГАЛЬНИЙ: усі p після h2 на тому ж рівні */
```

```html
<div class="card">
  <p>A</p>            <!-- .card p ✅   .card > p ✅ -->
  <div>
    <p>B</p>          <!-- .card p ✅   .card > p ❌ -->
  </div>
</div>
```

### 12.3. Селектори за атрибутами

```css
[disabled]                { }  /* є такий атрибут */
[type="email"]            { }  /* точне значення */
[href^="https://"]        { }  /* починається з */
[href$=".pdf"]            { }  /* закінчується на */
[href*="lnu"]             { }  /* містить */
[lang|="uk"]              { }  /* uk або uk-* */
[class~="card"]           { }  /* одне зі слів у списку */
```

Дуже практичний приклад — автоматична позначка зовнішніх посилань і PDF:

```css
a[href^="http"]::after      { content: " ↗"; }
a[href$=".pdf"]::after      { content: " (PDF)"; }
```

### 12.4. Псевдокласи

```css
/* Стани користувача */
a:hover, a:focus-visible   { }
button:active              { }
input:disabled             { }
input:checked              { }

/* Структурні */
li:first-child             { }
li:last-child              { }
li:nth-child(2)            { }
li:nth-child(odd)          { }     /* непарні */
li:nth-child(3n)           { }     /* кожен третій */
li:only-child              { }
p:empty                    { }

/* Логічні (Baseline: широко доступні) */
:is(h1, h2, h3) + p        { }     /* коротший запис групи */
:where(article, aside) p   { }     /* те саме, але зі специфічністю 0 */
li:not(.active)            { }     /* заперечення */
.card:has(img)             { }     /* «батьківський» селектор! */
```

🔑 **`:has()`** — довгоочікуваний «батьківський селектор». Дозволяє стилізувати
елемент залежно від його вмісту:

```css
/* Картка, у якій є зображення, отримує іншу сітку */
.card:has(img) { grid-template-rows: auto 1fr; }

/* Поле з помилкою підсвічує весь свій контейнер */
.field:has(input:user-invalid) { border-color: var(--color-danger); }
```

**Різниця `:is()` і `:where()`:** обидва скорочують запис, але `:is()` бере
найбільшу специфічність зі свого списку, а `:where()` завжди має специфічність
нуль. `:where()` ідеальний для базових стилів, які легко перевизначити.

### 12.5. Псевдоелементи

```css
.quote::before  { content: "«"; }
.quote::after   { content: "»"; }

p::first-line   { font-weight: 600; }
p::first-letter { font-size: 3em; float: left; }

::selection     { background: var(--color-accent); color: #fff; }
::placeholder   { color: #9aa4b2; }
input::file-selector-button { }
```

⚠️ `::before`/`::after` **не працюють** на порожніх (void) елементах:
`<img>`, `<input>`, `<br>`. І вимагають властивості `content` — без неї
нічого не з'явиться.

⚠️ Текст, доданий через `content`, — це **оформлення**, а не вміст. Його не
можна виділити й скопіювати, і екранні читачі поводяться з ним по-різному.
Ніколи не виносьте туди змістовну інформацію.

## 13. CSS: каскад, специфічність, успадкування

Це найважливіший розділ CSS. **90% ситуацій «чому мій стиль не працює?»**
пояснюються саме тут.

### 13.1. Каскад: порядок вирішення конфліктів

Коли до одного елемента застосовні кілька правил, браузер вирішує так
(за спаданням пріоритету):

1. **Походження й важливість**
   `!important` автора > стилі користувача > стилі автора > стилі браузера
2. **Каскадні шари** (`@layer`) — пізніші шари перемагають
3. **Специфічність** селектора
4. **Порядок у коді** — за інших рівних перемагає той, що нижче

### 13.2. Специфічність

Специфічність — трійка чисел **(A, B, C)**:

| Складник | Що рахується |
|---|---|
| **A** | кількість `#id` |
| **B** | кількість класів, атрибутів, псевдокласів |
| **C** | кількість елементів і псевдоелементів |

Порівнюються послідовно: спочатку A, при рівності — B, потім C.

| Селектор | Специфічність |
|---|---|
| `p` | (0, 0, 1) |
| `.card` | (0, 1, 0) |
| `p.card` | (0, 1, 1) |
| `.card .title` | (0, 2, 0) |
| `#header .nav a` | (1, 1, 1) |
| `style="…"` (інлайн) | перемагає все, крім `!important` |
| `!important` | окремий рівень над усім |

🔑 **(0, 1, 0) сильніше за (0, 0, 100).** Один клас переможе сотню селекторів за
іменем елемента. Специфічність — не сума, а трійка, що порівнюється зліва
направо.

```css
.button          { background: blue; }   /* (0,1,0) */
nav ul li a      { background: red;  }   /* (0,0,4) */
/* Переможе синій, хоча червоне правило нижче й «довше» */
```

**Особливі випадки:**

- `:not()`, `:is()`, `:has()` — самі по собі нічого не додають, але беруть
  найбільшу специфічність зі свого аргументу;
- `:where()` — завжди (0, 0, 0);
- універсальний селектор `*` і комбінатори (`>`, `+`, `~`) — нічого не додають.

### 13.3. `!important` — чому це майже завжди помилка

```css
.title { color: red !important; }
```

Виглядає як швидке рішення, але:

- перебиває каскад і ламає передбачуваність;
- перекрити його можна лише іншим `!important` із більшою специфічністю →
  далі «війна важливості»;
- через півроку ніхто не розуміє, чому щось не працює.

**Прийнятне застосування:** перевизначення стилів сторонньої бібліотеки, на яку
ви не впливаєте, та утилітарні класи. У власному коді — ознака того, що
структуру селекторів варто переглянути.

### 13.4. Каскадні шари `@layer`

Сучасний спосіб керувати пріоритетами без гри в специфічність:

```css
@layer reset, base, components, utilities;

@layer reset      { * { margin: 0; } }
@layer base       { body { font-family: system-ui; } }
@layer components { .card { padding: 1rem; } }
@layer utilities  { .mt-0 { margin-top: 0; } }
```

**Правила з пізнішого шару перемагають, незалежно від специфічності.** Це
означає, що утилітарний клас `.mt-0` переб'є `.card .header .title`, і жодних
`!important` не потрібно.

### 13.5. Успадкування

Частина властивостей передається дітям автоматично:

**Успадковуються:** `color`, `font-*`, `line-height`, `text-align`,
`letter-spacing`, `visibility`, `cursor`, `list-style`, `white-space`.

**Не успадковуються:** `margin`, `padding`, `border`, `background`, `width`,
`height`, `display`, `position`.

Керувати цим можна явно:

```css
.child {
  color: inherit;   /* взяти від батька */
  margin: initial;  /* значення за замовчуванням зі специфікації */
  border: unset;    /* inherit для успадкованих, initial для решти */
  padding: revert;  /* повернути до стилю браузера */
}
```

Класичний практичний прийом:

```css
/* Посилання й кнопки НЕ успадковують шрифт автоматично — задамо явно */
button, input, select, textarea {
  font: inherit;
  color: inherit;
}
```

### 13.6. Як налагоджувати «стиль не працює»

🧪 Алгоритм (виконуйте по черзі, це економить години):

1. **DevTools → Elements → Styles.** Перекреслене правило = його перебили.
   Наведіть — побачите, чим саме.
2. **Вкладка Computed** — реальне підсумкове значення властивості та звідки
   воно взялося.
3. Перевірте **специфічність** конкурентних селекторів.
4. Перевірте **написання**: `colour`, `padding-left: 10` (без одиниць),
   `background-color: #ff` — браузер мовчки ігнорує некоректні оголошення.
5. Перевірте, чи **застосовна** властивість: `width` не діє на рядкові
   (`inline`) елементи; `gap` — лише у flex/grid/multi-column.
6. Перевірте, що файл **справді підключився**: DevTools → Network, код 200,
   а не 404.
7. Скиньте кеш: `Ctrl+Shift+R` / `Cmd+Shift+R`.

## 14. CSS: блокова модель

### 14.1. Складники

```
┌─────────────────────────────────────────┐
│              margin (зовнішній відступ) │
│  ┌───────────────────────────────────┐  │
│  │           border (межа)           │  │
│  │  ┌─────────────────────────────┐  │  │
│  │  │   padding (внутрішній)      │  │  │
│  │  │  ┌───────────────────────┐  │  │  │
│  │  │  │   content (вміст)     │  │  │  │
│  │  │  │   width × height      │  │  │  │
│  │  │  └───────────────────────┘  │  │  │
│  │  └─────────────────────────────┘  │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

### 14.2. `box-sizing` — обов'язкове налаштування

За замовчуванням (`content-box`) `width` задає ширину **лише вмісту**, а
`padding` і `border` додаються **зверху**:

```css
.box { width: 300px; padding: 20px; border: 5px solid; }
/* Реальна ширина: 300 + 20·2 + 5·2 = 350px 😖 */
```

Тому в кожному проєкті першим рядком пишуть:

```css
*, *::before, *::after { box-sizing: border-box; }
```

Тепер `width: 300px` означає рівно 300 px разом із відступами й межами — саме
так, як інтуїтивно очікує людина.

### 14.3. Схлопування зовнішніх відступів

Вертикальні `margin` сусідніх або вкладених блоків **не додаються, а
схлопуються** — залишається більший:

```html
<p style="margin-bottom: 30px">Перший</p>
<p style="margin-top: 20px">Другий</p>
<!-- Відстань між ними — 30px, а не 50px -->
```

Схлопування **не відбувається**, якщо:

- є `padding` або `border` між блоками;
- батько є flex- або grid-контейнером;
- створено новий контекст форматування (`display: flow-root`, `overflow: auto`).

🔑 Практичний висновок: у Flexbox і Grid схлопування немає, тому сучасна
верстка з `gap` набагато передбачуваніша. Розповсюджена порада — задавати
відступи **лише в одному напрямку** (наприклад, тільки `margin-block-end`).

### 14.4. `display`

| Значення | Поведінка |
|---|---|
| `block` | займає всю ширину, починається з нового рядка (`div`, `p`, `section`) |
| `inline` | у рядку тексту; **`width`, `height` і вертикальні відступи не діють** (`span`, `a`, `em`) |
| `inline-block` | у рядку, але приймає розміри й відступи |
| `flex` / `inline-flex` | одновимірна розкладка (лекція 2) |
| `grid` / `inline-grid` | двовимірна розкладка (лекція 2) |
| `none` | елемент повністю зникає й не займає місця |
| `contents` | коробка зникає, діти лишаються (обережно з доступністю) |
| `flow-root` | створює новий контекст форматування |

⚠️ `display: none` проти `visibility: hidden` проти `opacity: 0`:

| | Займає місце | Клікабельний | Читає екранний читач |
|---|---|---|---|
| `display: none` | ні | ні | ні |
| `visibility: hidden` | **так** | ні | ні |
| `opacity: 0` | **так** | **так** ⚠️ | **так** ⚠️ |

Прозорий елемент лишається в потоці й ловить кліки — часте джерело
«невидимих» помилок.

### 14.5. Переповнення

```css
.box {
  overflow: visible;  /* за замовчуванням: вміст вилазить */
  overflow: hidden;   /* обрізати */
  overflow: auto;     /* смуга прокручування за потреби */
  overflow: scroll;   /* смуга завжди */
  overflow-x: auto;   /* окремо по осях */
}
```

Корисний прийом — обрізання довгого тексту:

```css
.truncate {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

/* Багаторядкове обрізання */
.clamp-3 {
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

## 15. CSS: одиниці виміру та кольори

### 15.1. Одиниці

| Одиниця | Що це | Коли застосовувати |
|---|---|---|
| `px` | піксель CSS | межі, тіні, брейкпойнти |
| `%` | відсоток від батька | ширини, розкладка |
| `em` | від розміру шрифту **поточного** елемента | внутрішні відступи, пов'язані з текстом |
| `rem` | від розміру шрифту **кореня** (`html`) | **основна одиниця**: розміри шрифту, відступи |
| `ch` | ширина символу «0» | обмеження довжини рядка (`max-width: 65ch`) |
| `vw`/`vh` | 1% ширини/висоти вікна | великі секції, героїчні блоки |
| `dvh`/`svh`/`lvh` | динамічна/мала/велика висота вікна | **мобільні**: враховують появу й зникнення панелей браузера |
| `fr` | частка вільного місця | лише в CSS Grid |

🔑 **Чому `rem`, а не `px`.** Якщо користувач збільшив базовий розмір шрифту в
налаштуваннях браузера (а так роблять люди зі слабким зором), розміри в `rem`
масштабуються разом із ним, а в `px` — ні. Це вимога WCAG.

⚠️ **Пастка `em`:** вони множаться. Якщо `.parent { font-size: 1.2em }` і
всередині `.child { font-size: 1.2em }`, дитина отримає 1.44 від початкового.
У вкладених списках це дає ефект «шрифт зникає». `rem` цієї проблеми не має.

⚠️ **Пастка `100vh` на мобільних:** адресний рядок то з'являється, то зникає, і
секція «на весь екран» стрибає. Використовуйте `100dvh`.

**Корисна порада щодо базового розміру.** Не задавайте `html { font-size: 62.5% }`
(щоб «1rem = 10px»): це ламає користувацькі налаштування розміру шрифту.
Залиште 16 px за замовчуванням і рахуйте у `rem` від нього.

### 15.2. Кольори

```css
color: #1f6fb2;                     /* HEX */
color: #1f6fb280;                   /* HEX з альфою (80 = 50%) */
color: rgb(31 111 178);             /* сучасний синтаксис, без ком */
color: rgb(31 111 178 / 50%);       /* з прозорістю */
color: hsl(206 71% 41%);            /* відтінок, насиченість, світлість */
color: oklch(55% 0.13 245);         /* перцептивно рівномірний простір */
color: color-mix(in oklch, var(--brand) 70%, white);
color: currentColor;                /* поточне значення color */
color: transparent;
```

🔑 **HSL зручний для варіацій:** щоб отримати світліший відтінок того самого
кольору, достатньо змінити третє число. **OKLCH** іде далі: у ньому однакова
зміна світлості *сприймається* однаково для всіх відтінків, тому палітри
виходять гармонійними. `oklch()` і `color-mix()` уже широко доступні.

Приклад побудови палітри на змінних:

```css
:root {
  --brand-h: 206;
  --brand-s: 71%;

  --brand-100: hsl(var(--brand-h) var(--brand-s) 92%);
  --brand-300: hsl(var(--brand-h) var(--brand-s) 72%);
  --brand-500: hsl(var(--brand-h) var(--brand-s) 41%);
  --brand-700: hsl(var(--brand-h) var(--brand-s) 28%);
}
```

### 15.3. Фони, межі, тіні

```css
.card {
  background-color: var(--color-surface);
  background-image: linear-gradient(180deg, #fff 0%, #f3f6fa 100%);

  border: 1px solid var(--color-border);
  border-radius: 12px;

  box-shadow:
    0 1px 2px rgb(0 0 0 / 6%),
    0 8px 24px rgb(0 0 0 / 8%);
}

.hero {
  background-image: url("../img/hero.jpg");
  background-size: cover;       /* заповнити, обрізавши зайве */
  background-position: center;
  background-repeat: no-repeat;
}
```

🔑 Дві накладені тіні (маленька різка + велика м'яка) виглядають значно
природніше, ніж одна. Це найдешевший спосіб зробити інтерфейс «дорожчим».

## 16. CSS: типографіка

Текст — це 95% вебу. Гарна типографіка робить більше для вигляду сайту, ніж
будь-які ефекти.

```css
:root {
  --font-sans: system-ui, -apple-system, "Segoe UI", Roboto,
               "Helvetica Neue", Arial, sans-serif;
  --font-mono: ui-monospace, "SF Mono", "Cascadia Code",
               "JetBrains Mono", Consolas, monospace;
}

body {
  font-family: var(--font-sans);
  font-size: 1rem;          /* 16px — не менше для основного тексту */
  line-height: 1.6;         /* без одиниць! */
  color: var(--color-text);
  text-wrap: pretty;        /* уникає «висячих» слів у кінці абзаців */
}

h1, h2, h3 {
  line-height: 1.2;         /* заголовкам потрібен щільніший інтерліньяж */
  text-wrap: balance;       /* рівномірно розподіляє слова заголовка */
}

p {
  max-width: 65ch;          /* 45–75 символів — оптимально для читання */
}
```

🔑 **`line-height` без одиниць.** `line-height: 1.6` означає «1.6 від власного
розміру шрифту елемента» і правильно успадковується. `line-height: 24px`
успадкується як фіксовані 24 px і зіпсує заголовки.

**Підключення шрифтів.**

```css
@font-face {
  font-family: "Inter";
  src: url("../fonts/inter-var.woff2") format("woff2-variations");
  font-weight: 100 900;      /* варіативний шрифт: увесь діапазон */
  font-display: swap;        /* показати текст запасним шрифтом, поки вантажиться */
}
```

`font-display: swap` рятує від «невидимого тексту» (FOIT) під час завантаження.
Формат **WOFF2** — обов'язковий, він найкраще стиснутий.

⚠️ Кожен підключений шрифт — це додатковий запит і затримка. Системний шрифтовий
стек (`system-ui`) не коштує нічого і гарно виглядає на кожній платформі.

**Читабельність — коротко:**

- довжина рядка 45–75 символів (`max-width: 65ch`);
- `line-height` 1.5–1.7 для основного тексту;
- не використовуйте світло-сірий текст на білому (контраст!);
- вирівнювання по лівому краю; `text-align: justify` без перенесення слів
  створює «річки» пробілів;
- не пишіть довгі фрагменти ВЕЛИКИМИ ЛІТЕРАМИ — читається повільніше.

## 17. CSS: власні властивості (змінні)

```css
:root {
  /* Кольори */
  --color-bg:      #ffffff;
  --color-surface: #f6f8fb;
  --color-text:    #17202a;
  --color-muted:   #5c6b7a;
  --color-accent:  #1f6fb2;
  --color-border:  #d8e0e9;
  --color-danger:  #c0392b;

  /* Відступи — узгоджена шкала */
  --space-1: 0.25rem;
  --space-2: 0.5rem;
  --space-3: 1rem;
  --space-4: 1.5rem;
  --space-5: 2.5rem;

  /* Інше */
  --radius: 12px;
  --shadow: 0 8px 24px rgb(0 0 0 / 8%);
  --transition: 200ms ease;
}

.card {
  background: var(--color-surface);
  padding: var(--space-4);
  border-radius: var(--radius);
  box-shadow: var(--shadow);
}
```

### Чим вони кращі за змінні препроцесорів

1. **Живуть у браузері**, а не зникають при компіляції.
2. **Успадковуються** й перевизначаються локально:

   ```css
   .card              { --card-bg: var(--color-surface); background: var(--card-bg); }
   .card--highlighted { --card-bg: #fff8e1; }   /* перевизначили лише змінну */
   ```

3. **Змінюються з JavaScript:**

   ```js
   document.documentElement.style.setProperty('--color-accent', '#e67e22');
   ```

4. **Роблять теми тривіальними** — перевизначаємо тільки змінні:

   ```css
   @media (prefers-color-scheme: dark) {
     :root {
       --color-bg:      #10151b;
       --color-surface: #18202a;
       --color-text:    #e8eef5;
       --color-muted:   #9aa9b8;
       --color-border:  #263241;
     }
   }
   ```

Значення за замовчуванням:

```css
padding: var(--card-padding, 1rem);   /* якщо змінної немає — 1rem */
```

залежать від глибини вкладеності.

## 19. Типові помилки

| # | Помилка | Чому погано | Як правильно |
|---|---|---|---|
| 1 | Немає `<meta name="viewport">` | Мобільна верстка не працює взагалі | Додати в `<head>` |
| 2 | Немає `<meta charset="utf-8">` | Кирилиця ламається | Додати першим у `<head>` |
| 3 | Верстка на самих `<div>` | Недоступно, погано для SEO, нечитабельний CSS | Семантичні елементи |
| 4 | Кілька `<h1>`, стрибки рівнів | Ламається структура документа | Один `<h1>`, послідовні рівні |
| 5 | `alt` відсутній або «фото» | Зображення недоступне | Осмислений опис або `alt=""` |
| 6 | Немає `width`/`height` у `<img>` | Стрибки верстки (CLS) | Вказувати завжди |
| 7 | `placeholder` замість `<label>` | Поле недоступне | Завжди `<label for>` |
| 8 | `<div onclick>` замість `<button>` | Недоступно з клавіатури | `<button>` / `<a href>` |
| 9 | `outline: none` без заміни | Неможливо орієнтуватися з клавіатури | `:focus-visible` зі своїм стилем |
| 10 | Стилі через `id` та `!important` | Війна специфічності | Класи, `@layer` |
| 11 | Немає `box-sizing: border-box` | Розміри «не сходяться» | Глобальний скид |
| 12 | `line-height: 24px` | Ламає заголовки при успадкуванні | `line-height: 1.6` |
| 13 | `100vh` на мобільних | Секція стрибає | `100dvh` |
| 14 | Абсолютні шляхи `/css/style.css` на GitHub Pages | 404 | Відносні шляхи |
| 15 | Інлайнові стилі `style="…"` | Неможливо перевизначити, дублювання | Зовнішній CSS |
| 16 | `<button>` без `type` у формі | Форма несподівано відправляється | `type="button"` |
| 17 | Світло-сірий текст на білому | Контраст нижче 4.5:1 | Перевірити контраст |
| 18 | Один коміт «final» наприкінці | Немає історії, не видно роботи | Коміти за логічними кроками |

## 20. Контрольні запитання

1. Що станеться, якщо прибрати `<!doctype html>`?
2. Чим `<meta charset>` відрізняється від заголовка `Content-Type`? Що з них
   має пріоритет?
3. Поясніть різницю між `GET` і `POST` через поняття безпечності та
   ідемпотентності.
4. Коли доречно повернути `401`, а коли `403`?
5. Чому фрагмент URL (`#section`) не потрапляє на сервер і як це
   використовували старі SPA?
6. Чим `defer` відрізняється від `async`? Що з них потрібно в 95% випадків?
7. Чому анімувати `transform` дешевше, ніж `left`?
8. Що потрапляє в Render Tree, а що ні? Чим у цьому сенсі `display: none`
   відрізняється від `visibility: hidden`?
9. Назвіть чотири переваги правильного `<label>`.
10. Обчисліть специфічність: `#main .list li a:hover`. Чи переможе вона
    `.nav__link--active`?
11. Що зробить `:where(article, aside) p { color: gray }` і чим це відрізняється
    від `:is(...)`?
12. Навіщо потрібен `box-sizing: border-box`?
13. У яких випадках вертикальні `margin` не схлопуються?
14. Чому `line-height` краще задавати без одиниць?
15. Чим `rem` кращий за `px` для розміру шрифту з погляду доступності?
16. Що таке Baseline і чим «newly available» відрізняється від «widely
    available»?
17. Сформулюйте перше правило ARIA і поясніть його сенс.
18. Чим `srcset` відрізняється від `<picture>`?

## 21. Практичні вправи

**Вправа 1 (розминка, 15 хв).** Відкрийте сайт свого факультету в DevTools.
Знайдіть: чи є `<meta viewport>`; скільки `<h1>` на сторінці; чи всі зображення
мають `alt`. Запишіть три знайдені проблеми.

**Вправа 2 (HTTP, 15 хв).** Відкрийте вкладку Network, перезавантажте сторінку
з `Ctrl+Shift+R`. Знайдіть: код стану головного документа; протокол
(HTTP/1.1, h2 чи h3); чи стиснуто відповідь (`Content-Encoding`); скільки
всього запитів і який сумарний розмір.

**Вправа 3 (семантика, 30 хв).** Дано розмітку:

```html
<div class="top">
  <div class="menu">
    <div class="item"><a href="#a">Про мене</a></div>
    <div class="item"><a href="#b">Проєкти</a></div>
  </div>
</div>
<div class="content">
  <div class="big-text">Моє портфоліо</div>
  <div class="block">
    <div class="title">Про мене</div>
    <div class="text">Текст…</div>
  </div>
</div>
<div class="bottom">© 2026</div>
```

Перепишіть її семантично. Перевірте результат у
[validator.w3.org](https://validator.w3.org/).

**Вправа 4 (форма, 30 хв).** Створіть форму реєстрації з полями: ім'я, e-mail,
пароль (мінімум 8 символів), дата народження, місто (`<select>`), згода з
умовами (`checkbox`). Вимоги: у кожного поля правильний `type`, `<label>`,
`autocomplete`, вбудована валідація; форма проходить перевірку валідатором;
усі поля доступні з клавіатури.

**Вправа 5 (специфічність, 15 хв).** Не запускаючи код, визначте колір тексту:

```html
<div id="wrap" class="theme">
  <p class="text important">Якого я кольору?</p>
</div>
```

```css
p                        { color: black; }
.text                    { color: blue; }
#wrap p                  { color: green; }
.theme .text.important   { color: orange; }
div p.text               { color: purple; }
```

Перевірте себе в браузері та поясніть результат через трійки специфічності.

**Вправа 6 (палітра, 30 хв).** Складіть у `:root` набір із 12+ CSS-змінних для
свого портфоліо: фон, поверхня, основний текст, приглушений текст, акцент,
межа, небезпека, успіх, п'ять кроків відступів, радіус, тінь. Перевірте
контраст «текст на фоні» та «приглушений текст на фоні» у WebAIM Contrast
Checker — обидві пари мають давати ≥ 4.5:1.

| Схлопування відступів | margin collapsing | Об'єднання сусідніх вертикальних `margin` |
| Псевдоклас | pseudo-class | Стан або позиція елемента (`:hover`, `:first-child`) |
| Псевдоелемент | pseudo-element | Віртуальна частина елемента (`::before`) |
| Власна властивість | custom property | CSS-змінна (`--color-accent`) |
| Критичний шлях рендерингу | critical rendering path | Послідовність кроків від HTML до пікселів |
| Перекомпонування | reflow / layout | Перерахунок геометрії елементів |
| Перемальовування | repaint | Повторне малювання без зміни геометрії |
| Стрибок верстки | layout shift | Зміщення вмісту після завантаження (метрика CLS) |
| Роздільна здатність незалежна | device pixel ratio | Співвідношення фізичних і CSS-пікселів |
| Брейкпойнт | breakpoint | Ширина, на якій змінюється макет |
| Ідемпотентність | idempotence | Повторний запит дає той самий результат |
| Кодування | character encoding | Правило перетворення байтів на символи (UTF-8) |
| Скид стилів | CSS reset | Вирівнювання стилів браузера за замовчуванням |
