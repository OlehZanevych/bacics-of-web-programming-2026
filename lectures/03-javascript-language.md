## Про що ця лекція

Ви вже вмієте описати структуру сторінки (HTML) та її вигляд (CSS). Лишилася
третя складова — **поведінка**. JavaScript — єдина мова програмування, яку
браузер виконує нативно, і тому вона є обов'язковою для будь-якого веброзробника.

Ця лекція — про **саму мову**: синтаксис, типи, функції, об'єкти, колекції.
Взаємодія зі сторінкою (DOM) — у лекції 4, асинхронність і мережа — у лекції 5.

JavaScript має репутацію мови з дивацтвами. Частково справедливо: її створили
за десять днів 1995 року, і через зобов'язання зворотної сумісності всі ранні
рішення лишилися назавжди. Але сучасний JavaScript (ES2015 і далі) — виразна й
потужна мова. Наше завдання — навчитися писати **сучасний** код і розуміти,
звідки беруться дивацтва, коли вони трапляються в чужому коді.

## Мета лекції

Після опрацювання ви:

- пояснюватимете різницю між `var`, `let` і `const` через області видимості
  та часову мертву зону;
- впевнено користуватиметеся примітивними й посилальними типами й
  розумітимете, чому `0.1 + 0.2 !== 0.3`;
- писатимете чисті функції, замикання й розумітимете, як визначається `this`;
- застосовуватимете методи масивів (`map`, `filter`, `reduce`) замість циклів
  там, де це доречно;
- обиратимете між об'єктом, `Map` і `Set` за характером задачі;
- організовуватимете код у ES-модулі.

## 1. JavaScript, ECMAScript і середовища виконання

**ECMAScript** — це стандарт мови (специфікація ECMA-262). **JavaScript** —
його найвідоміша реалізація. Комітет **TC39** щороку випускає нову редакцію:
ES2015 (ES6), ES2016, … ES2026. Кожна пропозиція проходить стадії 0→4; на
стадії 4 вона входить у стандарт.

🔑 Важливий висновок: не буває «JavaScript останньої версії». Питати треба
інакше — «які можливості підтримує **моє середовище виконання**».

**Середовища виконання (runtime):**

| Середовище | Двигун | Що додає понад мову |
|---|---|---|
| Браузер | V8 (Chrome/Edge), SpiderMonkey (Firefox), JavaScriptCore (Safari) | DOM, `fetch`, `localStorage`, таймери, події |
| Node.js | V8 | файлова система, мережа, процеси, модулі |
| Deno, Bun | V8 / JavaScriptCore | альтернативи Node.js |

🔑 `document`, `window`, `alert` — **не частина JavaScript**. Це API браузера.
У Node.js їх немає, зате є `fs` і `process`. Мова — це синтаксис, типи, об'єкти
на кшталт `Array`, `Math`, `JSON`, `Promise`.

## 2. Підключення до сторінки

```html
<!-- Найкращий варіант для сучасного коду: ES-модуль -->
<script type="module" src="js/main.js"></script>

<!-- Класичний скрипт, що не блокує парсинг -->
<script src="js/app.js" defer></script>

<!-- Вбудований код — лише для дрібниць і демо -->
<script>
  console.log('Привіт!');
</script>
```

Нагадування з лекції 1: `defer` завантажує паралельно й виконує після побудови
DOM, зберігаючи порядок. `type="module"` поводиться як `defer` за замовчуванням
і додатково вмикає строгий режим та власну область видимості файлу.

### Консоль — ваш головний інструмент

```js
console.log('звичайне повідомлення', змінна);
console.warn('попередження');
console.error('помилка');
console.table([{ id: 1, name: 'Аня' }, { id: 2, name: 'Богдан' }]);
console.group('Група'); console.log('усередині'); console.groupEnd();
console.time('обчислення'); /* … */ console.timeEnd('обчислення');
console.dir(element);              // об'єктне подання DOM-елемента
console.log({ user, cart, total }); // зручний трюк: імена змінних видно самі
```

🧪 Останній рядок — маленька, але дуже корисна звичка: замість
`console.log(user)` пишіть `console.log({ user })`, і в консолі буде видно
назву змінної.

## 3. Змінні та області видимості

```js
const PI = 3.14159;      // не можна перепризначити
let counter = 0;         // можна перепризначити
var old = 'застаріле';   // не використовуйте
```

### 3.1. Правило вибору

🔑 **`const` за замовчуванням. `let` — коли значення справді має змінюватися.
`var` — ніколи.**

```js
const user = { name: 'Аня' };
user.name = 'Анна';        // ✅ дозволено: змінюємо ВМІСТ об'єкта
user = { name: 'Інша' };   // ❌ TypeError: змінюємо саме ПОСИЛАННЯ
```

`const` забороняє **перепризначення змінної**, а не зміну об'єкта, на який вона
вказує. Щоб «заморозити» сам об'єкт, є `Object.freeze()` (поверхнево).

### 3.2. Області видимості

| | Область | Підняття (hoisting) | Повторне оголошення |
|---|---|---|---|
| `var` | функції | так, зі значенням `undefined` | дозволено |
| `let` | блоку `{}` | так, але в TDZ | заборонено |
| `const` | блоку `{}` | так, але в TDZ | заборонено |

```js
function demo() {
  if (true) {
    var a = 1;
    let b = 2;
  }
  console.log(a);   // 1   — var «протікає» за межі блоку
  console.log(b);   // ReferenceError
}
```

### 3.3. Підняття та часова мертва зона

**Hoisting** — оголошення «піднімаються» на початок своєї області.

```js
console.log(x);   // undefined  ← var піднято й ініціалізовано як undefined
var x = 5;

console.log(y);   // ReferenceError: Cannot access 'y' before initialization
let y = 5;
```

Проміжок від початку блоку до рядка оголошення називають **часовою мертвою
зоною (TDZ)**. Змінна вже існує, але звертатися до неї не можна. Це навмисне
рішення: краще явна помилка, ніж мовчазний `undefined`.

🔑 Класична пастка `var` у циклі — і чому `let` її розв'язує:

```js
// ❌ Виведе 3, 3, 3 — одна змінна на весь цикл
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}

// ✅ Виведе 0, 1, 2 — для кожної ітерації своя змінна
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

### 3.4. Строгий режим

```js
'use strict';
```

Вмикає суворіші правила: заборона неявних глобальних змінних, помилки замість
мовчазних збоїв, `this === undefined` у звичайних функціях. **У ES-модулях
строгий режим увімкнено завжди** — ще один аргумент на користь
`type="module"`.

## 4. Типи даних

### 4.1. Сім примітивів і об'єкти

**Примітиви** (незмінні, зберігаються за значенням):

```js
const s = 'текст';           // string
const n = 42;                // number
const b = true;              // boolean
const u = undefined;         // undefined — «значення не присвоєно»
const nl = null;             // null — «навмисно порожньо»
const big = 9007199254740993n;   // bigint
const sym = Symbol('id');    // symbol
```

**Об'єкти** (змінні, зберігаються за посиланням): `{}`, `[]`, функції, `Date`,
`Map`, `Set`, `RegExp`, `Error`.

```js
typeof 'текст'      // 'string'
typeof 42           // 'number'
typeof true         // 'boolean'
typeof undefined    // 'undefined'
typeof Symbol()     // 'symbol'
typeof 10n          // 'bigint'
typeof {}           // 'object'
typeof []           // 'object'   ← масив теж об'єкт
typeof function(){} // 'function'
typeof null         // 'object'   ← 🐛 історична помилка, яку не виправлять
```

Щоб надійно визначити масив: `Array.isArray(x)`.

### 4.2. Значення проти посилання

```js
// Примітиви копіюються за ЗНАЧЕННЯМ
let a = 5;
let b = a;
b = 10;
console.log(a);        // 5

// Об'єкти копіюються за ПОСИЛАННЯМ
const o1 = { n: 5 };
const o2 = o1;
o2.n = 10;
console.log(o1.n);     // 10 ← та сама пам'ять!
```

🔑 Це джерело №1 незрозумілих помилок у початківців. Дві змінні можуть
вказувати на **один** об'єкт. Про способи копіювання — розділ 15.

### 4.3. Числа: те, що обов'язково треба знати

Усі звичайні числа в JS — 64-бітові числа з рухомою комою (IEEE 754). Цілих
чисел як окремого типу немає.

```js
0.1 + 0.2 === 0.3          // false !
0.1 + 0.2                  // 0.30000000000000004
```

Це не «баг JavaScript» — так поводяться числа з рухомою комою в будь-якій мові.
Причина: 0.1 і 0.2 неможливо точно подати у двійковій системі, як 1/3 не можна
точно записати десятковим дробом.

**Як із цим працювати:**

```js
// Порівняння з допуском
const equal = Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON;   // true

// Гроші — тільки в цілих (копійках)!
const priceInKopecks = 12999;                       // 129.99 грн
const display = (priceInKopecks / 100).toFixed(2);  // "129.99"

// Форматування для користувача
new Intl.NumberFormat('uk-UA', {
  style: 'currency', currency: 'UAH'
}).format(129.99);   // "129,99 ₴"
```

Інші важливі моменти:

```js
Number.MAX_SAFE_INTEGER      // 9007199254740991 (2^53 − 1)
Number.isInteger(5.0)        // true
Number.isNaN(NaN)            // true  ← використовуйте цю, а не глобальну isNaN
NaN === NaN                  // false ← єдине значення, не рівне собі

parseInt('42px')             // 42
parseFloat('3.14abc')        // 3.14
Number('42')                 // 42
Number('42px')               // NaN
Number('')                   // 0    ⚠️ несподівано
+'42'                        // 42   (короткий запис)

(1234.5678).toFixed(2)       // "1234.57"  ← рядок!
Math.round(2.5)              // 3
Math.round(-2.5)             // -2  ⚠️ округлення «до плюс нескінченності»
Math.trunc(-4.7)             // -4
Math.floor(-4.7)             // -5
```

### 4.4. Рядки

```js
const name = 'Оксана';

// Шаблонні рядки — завжди надавайте перевагу їм
const greeting = `Привіт, ${name}! Тобі ${20 + 1} рік.`;
const multiline = `Перший рядок
Другий рядок`;

name.length                  // 6
name.toUpperCase()           // 'ОКСАНА'
name.includes('кса')         // true
name.startsWith('О')         // true
name.slice(0, 3)             // 'Окс'
name.at(-1)                  // 'а'  ← зручний доступ із кінця
'  текст  '.trim()           // 'текст'
'a,b,c'.split(',')           // ['a', 'b', 'c']
['a','b'].join('-')          // 'a-b'
'ха'.repeat(3)               // 'хахаха'
'5'.padStart(3, '0')         // '005'
'текст'.replaceAll('т', 'Т') // 'ТексТ'
```

🔑 **Рядки незмінні.** Жоден метод не змінює оригінал — усі повертають новий
рядок. `name.toUpperCase()` без присвоєння нічого не робить.

⚠️ **Кирилиця й `length`.** Для більшості українських літер усе гаразд, але
символи поза базовою площиною (емодзі, деякі знаки) займають дві одиниці:

```js
'😀'.length            // 2
[...'😀'].length       // 1  ← ітерація враховує кодові точки
```

**Порівняння рядків українською:**

```js
['Ґанок', 'Ялина', 'Іній', 'Аґрус'].sort();
// ['Ялина', 'Аґрус', 'Ґанок', 'Іній'] — сортування за кодами, неправильно

['Ґанок', 'Ялина', 'Іній', 'Аґрус'].sort((a, b) => a.localeCompare(b, 'uk'));
// ['Аґрус', 'Ґанок', 'Іній', 'Ялина'] — правильний український порядок
```

### 4.5. `null`, `undefined` і `NaN`

| Значення | Сенс | Коли з'являється |
|---|---|---|
| `undefined` | «значення ще не присвоєно» | неініціалізована змінна, відсутній аргумент, відсутня властивість, функція без `return` |
| `null` | «навмисно порожньо» | присвоюється розробником свідомо |
| `NaN` | «не число» | результат некоректної числової операції |

```js
let x;
console.log(x);            // undefined

const user = { name: 'Аня' };
console.log(user.age);     // undefined

const found = null;        // «шукали й не знайшли» — свідомо
```

## 5. Приведення типів і порівняння

### 5.1. Хибні (falsy) значення

Рівно **вісім** значень вважаються хибними:

```js
false, 0, -0, 0n, '', null, undefined, NaN
```

**Усе інше** — істинне, зокрема:

```js
Boolean('0')        // true  ⚠️ непорожній рядок
Boolean('false')    // true  ⚠️
Boolean([])         // true  ⚠️ порожній масив!
Boolean({})         // true  ⚠️ порожній об'єкт!
Boolean(-1)         // true
```

⚠️ **Найпоширеніша пастка:** `if (arr)` завжди істинне, навіть для порожнього
масиву. Перевіряйте `if (arr.length > 0)`.

### 5.2. `==` проти `===`

```js
5 === '5'        // false — різні типи
5 == '5'         // true  — рядок приведено до числа

null == undefined   // true   ← єдиний корисний випадок «==»
null === undefined  // false

'' == 0             // true  ⚠️
'0' == 0            // true  ⚠️
'' == '0'           // false ⚠️⚠️ порушує транзитивність!
[] == false         // true  ⚠️
[] == ![]           // true  ⚠️ класика «WTF JS»
```

🔑 **Правило без винятків: завжди `===` і `!==`.** Єдиний прийнятний виняток —
`x == null` для перевірки «`null` або `undefined`» одним виразом. Але й тут
є чіткіші засоби (див. `??` нижче).

### 5.3. Приведення при `+`

```js
1 + '2'          // '12'   ← число стає рядком
'3' - 1          // 2      ← рядок стає числом (мінус працює лише з числами)
'3' * '4'        // 12
true + 1         // 2
[] + {}          // '[object Object]'
```

`+` перевантажений: якщо хоч один операнд — рядок, це конкатенація. Решта
арифметичних операторів завжди приводять до числа.

### 5.4. Логічні оператори та сучасні альтернативи

```js
a && b     // якщо a хибне — повертає a, інакше b
a || b     // якщо a істинне — повертає a, інакше b
!a         // заперечення

a ?? b     // ← nullish coalescing: b лише якщо a є null або undefined
```

🔑 **`??` проти `||` — важлива відмінність:**

```js
const count = 0;
console.log(count || 10);   // 10 ⚠️ нуль хибний, але ж він валідне значення!
console.log(count ?? 10);   // 0  ✅

const name = '';
console.log(name || 'Гість');   // 'Гість'
console.log(name ?? 'Гість');   // ''  ← порожній рядок теж може бути валідним
```

Для значень за замовчуванням у 90% випадків потрібен саме `??`.

**Опціональний ланцюжок `?.`:**

```js
const user = { profile: { city: 'Львів' } };

user.profile.city        // 'Львів'
user.address.city        // ❌ TypeError
user.address?.city       // undefined  ✅
user.getName?.()         // виклик, лише якщо метод існує
arr?.[0]                 // безпечний доступ до елемента
```

**Оператори присвоєння:**

```js
x ||= 10;      // якщо x хибне — присвоїти 10
y ??= 10;      // якщо y null/undefined — присвоїти 10
z &&= 5;       // якщо z істинне — присвоїти 5
```

## 6. Оператори, умови, цикли

### 6.1. Умови

```js
if (score >= 90)      grade = 'A';
else if (score >= 80) grade = 'B';
else                  grade = 'C';

// Тернарний оператор — для коротких виразів
const label = count === 1 ? 'товар' : 'товари';

// switch — обов'язково з break!
switch (status) {
  case 'loading':
    render(spinner);
    break;
  case 'error':
  case 'failed':          // кілька значень підряд
    render(errorMessage);
    break;
  default:
    render(content);
}
```

⚠️ `switch` порівнює через `===`. І забутий `break` спричиняє «провал» до
наступного випадку — джерело важковловимих помилок.

Часто замість `switch` чистіше використати об'єкт-довідник:

```js
const renderers = {
  loading: () => render(spinner),
  error:   () => render(errorMessage),
  success: () => render(content),
};
(renderers[status] ?? renderers.success)();
```

### 6.2. Цикли

```js
// Класичний for — коли потрібен індекс
for (let i = 0; i < arr.length; i++) { … }

// for...of — по ЗНАЧЕННЯХ (масиви, рядки, Set, Map, NodeList)
for (const item of items) { … }

// з індексом
for (const [i, item] of items.entries()) { … }

// for...in — по КЛЮЧАХ об'єкта (для масивів не використовуйте!)
for (const key in obj) { … }

while (condition) { … }
do { … } while (condition);

// Керування
break;      // вийти з циклу
continue;   // перейти до наступної ітерації
```

⚠️ **Не використовуйте `for...in` для масивів.** Він перебирає ключі як **рядки**,
включно з тими, що успадковані з прототипу, і не гарантує порядку. Для масивів —
`for...of` або методи (`forEach`, `map`).

🔑 На практиці в сучасному коді цикли зустрічаються рідко: більшість задач
елегантніше розв'язуються методами масивів (розділ 12).

## 7. Функції

### 7.1. Три способи оголосити

```js
// 1. Оголошення функції (function declaration) — піднімається повністю
function add(a, b) {
  return a + b;
}

// 2. Функціональний вираз — не піднімається
const subtract = function (a, b) {
  return a - b;
};

// 3. Стрілкова функція — коротко, без власного this
const multiply = (a, b) => a * b;
const square = x => x * x;              // один параметр — дужки не обов'язкові
const greet = () => 'Привіт';           // немає параметрів — дужки обов'язкові
const makeUser = name => ({ name });    // повертаємо об'єкт — потрібні круглі дужки!
const process = (a, b) => {             // тіло з кількох рядків — потрібен return
  const sum = a + b;
  return sum * 2;
};
```

```js
console.log(add(2, 3));       // 5 — працює, оголошення піднято
console.log(subtract(5, 2));  // ReferenceError — вираз не піднято
```

### 7.2. Параметри

```js
// Значення за замовчуванням
function greet(name = 'Гість', greeting = 'Привіт') {
  return `${greeting}, ${name}!`;
}

// Rest — «решта аргументів» у справжній масив
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
sum(1, 2, 3, 4);   // 10

// Іменовані параметри через деструктуризацію об'єкта

  return { name, email, role, isActive };
}

```

🔑 **Іменовані параметри — важлива практика.** Порівняйте:

```js

```

об'єкт. Це знадобиться вже в Завданні №2.

### 7.3. Стрілкові функції: чим відрізняються

| | Звичайна | Стрілкова |
|---|---|---|
| Власний `this` | так | **ні** (бере з місця оголошення) |
| `arguments` | є | немає (використовуйте rest) |
| Можна викликати з `new` | так | **ні** |
| Підняття | оголошення — так | ні |
| Придатна як метод об'єкта | так | **ні** (див. розділ 9) |

```js
// Стрілкові ідеальні для колбеків

const adults = users.filter(u => u.age >= 18);

setTimeout(() => console.log('готово'), 1000);
```

### 7.4. Чисті функції

**Чиста функція** — та, що (1) за однакових аргументів завжди повертає той
самий результат і (2) не має побічних ефектів (не змінює зовнішній стан, не
пише в DOM, не звертається до мережі).

```js
// ✅ Чиста
const applyDiscount = (price, percent) => price * (1 - percent / 100);

// ❌ Нечиста: змінює зовнішній стан
let total = 0;
function addToTotal(x) { total += x; }

// ❌ Нечиста: мутує аргумент
function addItem(cart, item) {
  cart.push(item);        // змінили переданий масив!
  return cart;
}

// ✅ Чиста версія
const addItem = (cart, item) => [...cart, item];
```

🔑 Чисті функції легко тестувати, легко читати й неможливо «випадково зламати»
десь у сусідньому файлі. Це стане критично важливим у React (лекція 8), де
редюсер **зобов'язаний** бути чистою функцією.

## 8. Замикання

**Замикання (closure)** — функція разом із «запам'ятаним» лексичним оточенням,
у якому вона була створена. Простіше: внутрішня функція **пам'ятає** змінні
зовнішньої навіть після того, як зовнішня завершилася.

```js
function makeCounter() {
  let count = 0;                    // «приватна» змінна

  return {
    increment() { return ++count; },
    decrement() { return --count; },
    get value() { return count; },
  };
}

const counter = makeCounter();
counter.increment();     // 1
counter.increment();     // 2
counter.value;           // 2
counter.count;           // undefined ← ззовні не дістатися
```

**Практичні застосування** (усі знадобляться в Завданні №2):

```js
// Генератор унікальних ідентифікаторів
function makeIdGenerator(prefix = 'note') {
  let n = 0;
  return () => `${prefix}-${++n}`;
}
const nextId = makeIdGenerator();
nextId();   // 'note-1'
nextId();   // 'note-2'

// Debounce: викликати функцію лише після паузи в подіях
function debounce(fn, delay = 300) {
  let timerId;
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delay);
  };
}

const saveState = debounce(() => localStorage.setItem('notes', JSON.stringify(notes)), 300);

// Throttle: викликати не частіше ніж раз на interval
function throttle(fn, interval = 100) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn(...args);
    }
  };
}
```

⚠️ Замикання утримують змінні в пам'яті. Якщо ви створюєте багато замикань, що
захоплюють великі об'єкти, і не звільняєте посилання на них — це витік пам'яті.

## 9. `this` та контекст виклику

`this` у JavaScript визначається **не місцем оголошення функції, а способом її
виклику**. Це найчастіше джерело плутанини.

```js
// 1. Звичайний виклик: undefined (строгий режим) або globalThis
function f() { console.log(this); }
f();

// 2. Метод об'єкта: сам об'єкт
const obj = {
  name: 'Об\'єкт',
  greet() { console.log(this.name); },
};
obj.greet();               // 'Об'єкт'

// 3. Втрата контексту ⚠️
const g = obj.greet;
g();                       // undefined — виклик уже не «через крапку»

// 4. Явне задання
g.call(obj);               // 'Об'єкт'
g.apply(obj);              // те саме, аргументи масивом
const bound = g.bind(obj); // нова функція з назавжди зафіксованим this
bound();                   // 'Об'єкт'

// 5. З new: новий об'єкт
function User(name) { this.name = name; }
const u = new User('Аня');

// 6. Стрілкова: бере this з місця ОГОЛОШЕННЯ
const timer = {
  seconds: 0,
  start() {
    setInterval(() => {
      this.seconds++;      // ✅ this === timer, бо стрілкова
    }, 1000);
  },
};
```

⚠️ **Класична помилка:** стрілкова функція як метод об'єкта.

```js
const bad = {
  name: 'Об\'єкт',
  greet: () => console.log(this.name),   // ❌ this — не об'єкт!
};
bad.greet();   // undefined
```

Стрілкова функція бере `this` із зовнішньої області, а на верхньому рівні
модуля це не об'єкт.

🔑 **Практичне правило для цього курсу:** методи об'єктів і класів —
звичайні функції; колбеки всередині них — стрілкові.

## 11. Прототипи та класи

### 11.1. Прототипне успадкування

У JavaScript немає класів у класичному сенсі. Є **прототипи**: кожен об'єкт має
приховане посилання на інший об'єкт-прототип. Якщо властивість не знайдено в
самому об'єкті, пошук іде вгору по **ланцюжку прототипів**.

```js
const animal = {
  eat() { return `${this.name} їсть`; },
};

const dog = Object.create(animal);
dog.name = 'Рекс';
dog.eat();                     // 'Рекс їсть' — метод узято з прототипу
Object.getPrototypeOf(dog) === animal;   // true
```

Саме тому в масиву є `map`, хоч ви його не оголошували: він лежить у
`Array.prototype`.

### 11.2. Класи

`class` — синтаксичний цукор над прототипами, але значно читабельніший.

```js
class Note {
  // Приватні поля (справді приватні, не за домовленістю)
  #createdAt;

  // Статична властивість
  static maxLength = 500;

  constructor({ id, text = '', x = 0, y = 0, color = 'yellow' }) {
    this.id = id;
    this.text = text;
    this.x = x;
    this.y = y;
    this.color = color;
    this.#createdAt = new Date();
  }

  get preview() {
    return this.text.slice(0, 40) + (this.text.length > 40 ? '…' : '');
  }

  get age() {
    return Date.now() - this.#createdAt.getTime();
  }

  moveTo(x, y) {
    this.x = x;
    this.y = y;
    return this;                       // дозволяє ланцюжок викликів
  }

  setText(text) {
    if (text.length > Note.maxLength) {
      throw new RangeError(`Максимум ${Note.maxLength} символів`);
    }
    this.text = text;
    return this;
  }

  toJSON() {
    const { id, text, x, y, color } = this;
    return { id, text, x, y, color };
  }

  static fromJSON(data) {
    return new Note(data);
  }
}

const note = new Note({ id: 'n1', text: 'Купити молоко' });
note.moveTo(120, 80).setText('Купити молоко і хліб');
console.log(note.preview);
```

**Успадкування:**

```js
class PinnedNote extends Note {
  constructor(options) {
    super(options);            // виклик конструктора батька — ОБОВ'ЯЗКОВО перший
    this.pinned = true;
  }

  toJSON() {
    return { ...super.toJSON(), pinned: this.pinned };
  }
}
```

🔑 У цьому курсі класи знадобляться рідко: React (лекції 6–10) використовує
функціональний підхід, а для більшості задач достатньо звичайних об'єктів.
Але розуміти клас треба — ви зустрінете їх у чужому коді та у власних помилках
(`class Error extends …`).

## 12. Масиви та їхні методи

### 12.1. Основи

```js
const fruits = ['яблуко', 'банан', 'вишня'];

fruits.length            // 3
fruits[0]                // 'яблуко'
fruits.at(-1)            // 'вишня' — доступ із кінця

Array.isArray(fruits)    // true
Array.from('абв')        // ['а', 'б', 'в']
Array.from({ length: 5 }, (_, i) => i * 2);   // [0, 2, 4, 6, 8]
Array.of(7)              // [7]  (на відміну від new Array(7))
```

### 12.2. Методи, що ЗМІНЮЮТЬ масив

```js
const arr = [1, 2, 3];

arr.push(4);         // додати в кінець    → [1,2,3,4], повертає нову довжину
arr.pop();           // забрати з кінця    → повертає елемент
arr.unshift(0);      // додати на початок  (повільно для великих масивів)
arr.shift();         // забрати з початку
arr.splice(1, 2);    // видалити 2 елементи з індексу 1
arr.splice(1, 0, 'x');   // вставити 'x' на позицію 1, нічого не видаляючи
arr.sort();          // ⚠️ сортує НА МІСЦІ
arr.reverse();       // ⚠️ теж на місці
```

⚠️ **`sort()` за замовчуванням сортує як рядки!**

```js
[10, 9, 100, 1].sort();                 // [1, 10, 100, 9]  ❌
[10, 9, 100, 1].sort((a, b) => a - b);  // [1, 9, 10, 100]  ✅
```

### 12.3. Методи, що ПОВЕРТАЮТЬ новий масив

```js
const nums = [1, 2, 3, 4, 5];

nums.map(n => n * 2)                // [2,4,6,8,10]      — перетворити кожен
nums.filter(n => n % 2 === 0)       // [2,4]             — залишити відповідні
nums.slice(1, 3)                    // [2,3]             — вирізати частину
nums.concat([6, 7])                 // [1,…,7]
[[1,2],[3,[4]]].flat(2)             // [1,2,3,4]
nums.flatMap(n => [n, n * 10])      // [1,10,2,20,…]

// Незмінювані аналоги мутуючих методів (сучасні, широко доступні)
nums.toSorted((a, b) => b - a)      // новий відсортований, оригінал цілий
nums.toReversed()
nums.toSpliced(1, 2)
nums.with(0, 99)                    // копія зі зміненим елементом
```

🔑 `toSorted`, `toReversed`, `with` — дуже зручні, коли не можна мутувати
початковий масив (а в React це заборонено завжди).

### 12.4. Пошук і перевірка

```js
nums.find(n => n > 3)          // 4          — перший відповідний елемент
nums.findIndex(n => n > 3)     // 3          — його індекс
nums.findLast(n => n < 4)      // 3
nums.includes(3)               // true
nums.indexOf(3)                // 2
nums.some(n => n > 4)          // true       — «хоч один»
nums.every(n => n > 0)         // true       — «усі»
```

### 12.5. `reduce` — найпотужніший і найстрашніший

```js
// Сума
const total = nums.reduce((acc, n) => acc + n, 0);          // 15

// Максимум
const max = nums.reduce((acc, n) => (n > acc ? n : acc), -Infinity);

// Групування за полем — дуже частий випадок
const byCity = users.reduce((acc, user) => {
  (acc[user.city] ??= []).push(user);
  return acc;
}, {});
// { 'Львів': [...], 'Київ': [...] }

// Підрахунок
const counts = ['a', 'b', 'a'].reduce((acc, x) => {
  acc[x] = (acc[x] ?? 0) + 1;
  return acc;
}, {});
// { a: 2, b: 1 }
```

Сигнатура: `reduce((акумулятор, елемент, індекс, масив) => новийАкумулятор, початковеЗначення)`.

⚠️ **Завжди вказуйте початкове значення.** Без нього `reduce` на порожньому
масиві кидає `TypeError`.

🔑 Не намагайтеся зробити все через `reduce`. Якщо код із `reduce` важче
читати, ніж звичайний цикл, — беріть цикл. Читабельність важливіша за
«функціональність».

### 12.6. Ланцюжки

const result = products
  .filter(p => p.inStock)
  .filter(p => p.price <= budget)
  .map(p => ({ ...p, priceWithVat: p.price * 1.2 }))

### 12.7. `forEach` проти `map`

```js
// forEach — для побічних ефектів, нічого не повертає
items.forEach(item => console.log(item));

// map — для перетворення, повертає новий масив
const names = items.map(item => item.name);

// ❌ Так не треба
const wrong = items.forEach(item => item.name);   // undefined
```

⚠️ З `forEach` **не можна вийти достроково**: `break` не працює, `return`
пропускає лише поточну ітерацію. Потрібен вихід — беріть `for...of`,
`some` або `find`.

## 13. Колекції: Set, Map, WeakMap

### 13.1. `Set` — множина унікальних значень

```js
const tags = new Set(['js', 'css', 'js', 'html']);
tags.size            // 3 — дублікати відкинуто

tags.add('react');
tags.has('css');     // true — перевірка за O(1)
tags.delete('js');
[...tags];           // назад у масив

// Найчастіше застосування — прибрати дублікати
const unique = [...new Set([1, 2, 2, 3, 3, 3])];   // [1, 2, 3]
```

### 13.2. `Map` — словник із ключами будь-якого типу

```js
const notes = new Map();

notes.set('n1', { text: 'Перший' });
notes.set('n2', { text: 'Другий' });

notes.get('n1');      // { text: 'Перший' }
notes.has('n2');      // true
notes.delete('n1');
notes.size;           // 1

for (const [id, note] of notes) {
  console.log(id, note.text);
}

[...notes.keys()];    // масив ключів
[...notes.values()];  // масив значень
```

**`Map` проти об'єкта:**

| | Об'єкт `{}` | `Map` |
|---|---|---|
| Ключі | лише рядки й символи | **будь-який тип**, зокрема об'єкти |
| Порядок | складні правила (числові ключі йдуть першими) | порядок вставки гарантовано |
| Розмір | `Object.keys(o).length` | `map.size` |
| Ітерація | через `Object.entries` | напряму, це ітерований об'єкт |
| Часті додавання/видалення | повільніше | швидше |
| Серіалізація в JSON | нативна | треба перетворювати вручну |

🔑 **Правило вибору:** якщо ключі — заздалегідь відомі імена полів (структура
запису), беріть об'єкт. Якщо це справжній словник із динамічними ключами,
куди постійно додають і звідки видаляють, — `Map`. У Завданні №2 стан дошки
стікерів природно зберігати саме в `Map` (`id → нотатка`).

### 13.3. `WeakMap` і `WeakSet`

Ключами можуть бути лише об'єкти, і ці посилання **не заважають збиранню
сміття**. Використовуються, щоб прив'язати додаткові дані до об'єкта без ризику
витоку пам'яті:

```js
const metadata = new WeakMap();

function attach(element, data) {
  metadata.set(element, data);
}
// Коли DOM-елемент видалять зі сторінки, запис зникне автоматично.
```

## 14. Деструктуризація, spread і rest

### 14.1. Деструктуризація об'єктів

```js
const user = { name: 'Аня', age: 20, city: 'Львів', role: 'student' };

const { name, age } = user;
const { name: userName } = user;                 // перейменування

// rest → { age: 20, city: 'Львів', role: 'student' }

// Вкладена деструктуризація
const config = { server: { host: 'localhost', port: 3000 } };
const { server: { host, port } } = config;
```

### 14.2. Деструктуризація масивів

```js
const coords = [10, 20, 30];

const [x, y] = coords;
const [first, , third] = coords;         // пропустити елемент
const [head, ...tail] = coords;          // head = 10, tail = [20, 30]
const [a = 0, b = 0, c = 0, d = 0] = coords;   // d = 0

// Обмін значень без тимчасової змінної
let p = 1, q = 2;
[p, q] = [q, p];
```

### 14.3. Spread

```js
// Масиви
const combined = [...arr1, ...arr2];
const copy = [...arr];
const withNew = [...arr, newItem];             // додати без мутації
const withoutItem = arr.filter(x => x.id !== id);

// Об'єкти
const updated = { ...user, age: 21 };          // змінити поле без мутації
const merged = { ...defaults, ...overrides };

// Аргументи функції
Math.max(...numbers);
```

🔑 Spread — головний інструмент **незмінного** оновлення даних. Саме так
оновлюють стан у React (лекції 6–8) і в редюсері Завдання №3.

```js
// Оновити один елемент масиву об'єктів без мутації
const updatedNotes = notes.map(note =>
  note.id === targetId ? { ...note, text: newText } : note
);
```

## 15. Копіювання: поверхневе та глибоке

```js
const original = {
  name: 'Аня',
  address: { city: 'Львів' },
};

// Поверхнева копія: вкладені об'єкти СПІЛЬНІ
const shallow = { ...original };
shallow.name = 'Оксана';              // ✅ оригінал не змінився
shallow.address.city = 'Київ';        // ⚠️ original.address.city теж 'Київ'!

// Глибока копія
const deep = structuredClone(original);   // ✅ сучасний вбудований спосіб
deep.address.city = 'Одеса';              // оригінал не постраждав
```

`structuredClone()` — вбудована функція, працює з вкладеними об'єктами,
масивами, `Map`, `Set`, `Date`, типізованими масивами. **Не копіює функції**
(і кидає помилку, якщо вони є).

Старий трюк `JSON.parse(JSON.stringify(obj))` теж працює, але:

- втрачає `undefined`, функції, `Symbol`;
- перетворює `Date` на рядок;
- не працює з циклічними посиланнями;
- повільніший.

🔑 Використовуйте `structuredClone`, коли справді потрібна глибока копія. Але
частіше правильна відповідь — **не мутувати взагалі**, а створювати нові
структури через spread і `map`.

## 16. JSON

**JSON (JavaScript Object Notation)** — текстовий формат обміну даними.
Синтаксично схожий на об'єкти JS, але це **рядок** і правила суворіші.

```js
const obj = { name: 'Аня', age: 20, tags: ['js'], active: true };

const json = JSON.stringify(obj);
// '{"name":"Аня","age":20,"tags":["js"],"active":true}'

const parsed = JSON.parse(json);

// Форматований вивід (для налагодження й файлів)
JSON.stringify(obj, null, 2);

// Вибіркова серіалізація
JSON.stringify(obj, ['name', 'age']);            // лише ці поля
JSON.stringify(obj, (key, value) =>              // функція-заміна
  key === 'password' ? undefined : value
);
```

**Відмінності JSON від об'єкта JS:**

| | JSON | Об'єкт JS |
|---|---|---|
| Ключі | лише в подвійних лапках | без лапок або в будь-яких |
| Рядки | лише подвійні лапки | одинарні, подвійні, зворотні |
| Кома в кінці | заборонена | дозволена |
| Коментарі | заборонені | дозволені |
| Типи | string, number, boolean, null, array, object | усі |
| `undefined`, функції | **не підтримуються** | підтримуються |

⚠️ **`JSON.parse` кидає виняток на некоректному рядку.** Дані з
`localStorage` чи з мережі завжди можуть виявитися пошкодженими:

```js
function safeParse(json, fallback = null) {
  try {
    return JSON.parse(json);
  } catch {
    console.warn('Не вдалося розібрати JSON, використано значення за замовчуванням');
    return fallback;
  }
}

const notes = safeParse(localStorage.getItem('notes'), []);
```

Це прямо потрібно в Завданні №2 (вимога «застосунок не має падати на
пошкоджених даних»).

## 18. Помилки та їх обробка

```js
try {
  const data = JSON.parse(input);
  process(data);
} catch (error) {
  console.error('Не вдалося обробити дані:', error.message);
} finally {
  hideSpinner();          // виконається завжди
}
```

**Вбудовані типи помилок:** `Error`, `TypeError`, `RangeError`,
`SyntaxError`, `ReferenceError`.

**Власні помилки:**

```js
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
  }
}

function validateNote(text) {
  if (!text.trim()) {
    throw new ValidationError('Текст не може бути порожнім', 'text');
  }
  if (text.length > 500) {
    throw new ValidationError('Максимум 500 символів', 'text');
  }
}

try {
  validateNote('');
} catch (error) {
  if (error instanceof ValidationError) {
    showFieldError(error.field, error.message);
  } else {
    throw error;             // невідома помилка — прокидаємо далі
  }
}
```

🔑 **Не ковтайте помилки мовчки.** Порожній `catch {}` — найгірше, що можна
зробити: програма продовжить працювати у зламаному стані, і причину ви вже не
знайдете. Або обробіть змістовно, або дайте помилці піднятися.

⚠️ `try/catch` **не ловить** помилки з асинхронних колбеків:

```js
try {
  setTimeout(() => { throw new Error('бум'); }, 100);
} catch {
  // сюди не потрапимо — колбек виконається пізніше й поза цим блоком
}
```

Як обробляти асинхронні помилки — тема лекції 5.
